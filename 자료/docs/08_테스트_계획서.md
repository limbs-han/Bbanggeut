# 윌리엄 제임스 테스트 계획서

> 문서 버전: 1.0  
> 기준 요구사항: `01_요구사항_명세서.md`  
> 현재 상태: 계획 수립 완료, 테스트 결과는 모두 `미실행`  
> 주의: 이 문서는 예상 결과를 정의하며 실제 통과를 의미하지 않는다.

## 1. 테스트 목적

- 웃음·호출어·터치 이벤트가 요구된 과거·미래 구간의 영상으로 만들어지는지 검증한다.
- Flutter 앱, Spring Boot, IoT/AI, FFmpeg, DB 및 MinIO/S3의 종단간 연동을 검증한다.
- 기기별 `OWNER/MEMBER`, `DeviceMembership` 기반 영상 격리, 서명 URL, 기기 인증이 우회되지 않는지 검증한다.
- 네트워크 끊김, 저장소 실패, 재부팅, 권한 회수, 삭제 실패 같은 장애 상황에서 데이터가 유실·중복·노출되지 않는지 검증한다.
- `[기본]`과 `[심화]` 결과를 분리해 MVP 완료 여부를 판정한다.

## 2. 범위와 우선순위

| 우선순위 | 범위 | 실행 원칙 |

| 영역 | 기준 환경 | 기록할 값 |
| --- | --- | --- |
| 앱 | Flutter Android 디버그/릴리스 빌드, 기준 Android 실기기 1대 이상, 서로 다른 화면 크기 2종 | 앱 버전, OS, 기종, 화면 크기 |

| 저장소 | MinIO 또는 AWS S3 비공개 버킷 | 제품·버전, 버킷 정책, URL 만료 설정 |
| IoT | Jetson Orin Nano, Raspberry Pi 5, USB 카메라·마이크, TTP223B, LED | OS, 보드, 모델·스크립트 커밋, 세그먼트 길이 |
| AI | YAMNet, YOLO, 호출어 모델, 선택적 MediaPipe | 모델 이름·버전, 임계값, 입력 장치 |
| 영상 | FFmpeg, H.264/AAC MP4, 온디맨드 HLS | FFmpeg 버전, 해상도, FPS, GOP·keyframe/HLS 세그먼트 길이, tee/remux 명령과 재인코딩 여부 |
| 네트워크 | 정상 Wi-Fi/LAN, 네트워크 차단·지연을 재현할 수 있는 환경 | 대역폭, 지연, 차단 구간, 복구 시각 |

라이브 시험에서는 PENDING 생성 즉시 `lastActivityAt=createdAt`, `viewerExpiresAt=createdAt+45초`, `stopDeadline=createdAt+60초`인지 먼저 확인한다. 이후 15초 heartbeat·45초 TTL·마지막 유효 활동 기준 최대 60초 stop·120초 `hardExpiresAt`을 기록한다. playlist·segment는 세션 소유자와 `ACTIVE DeviceMembership`을 매 요청 또는 매우 짧은 introspection token으로 검증한다. 저장 영상 S3 서명 URL과 혼용하지 않으며 이미 받은 바이트는 회수할 수 없음을 결과에 남긴다. Redis는 전제하지 않는다.

운영 비밀번호·토큰·제품 코드는 테스트 문서나 Git에 기록하지 않는다. 테스트용 자격 증명은 별도 비밀 관리 채널에서 전달한다.

## 6. 진입·종료 기준

### 진입 기준

- 대상 기능의 요구사항과 API/메시지 계약이 고정되어 있다.
- 테스트 환경에서 앱, 백엔드, DB, 저장소 및 대상 기기를 식별할 수 있다.
- 개인정보가 없는 테스트 영상·음원과 계정이 준비되어 있다.
- 로그 시각이 비교 가능하도록 서버와 기기의 시간이 동기화되어 있다.
- 테스트 결과서에 빌드·환경·증거를 기록할 수 있다.

### 기본 MVP 종료 기준

- 모든 `[기본]` P0·P1 테스트가 실행되어 실제 결과와 증거가 기록되어 있다.
- P0 미해결 결함이 0건이다.
- P1 미해결 결함은 PM과 담당자의 명시적 수용 기록이 있어야 한다.
- 요구사항 추적성 매트릭스에서 모든 `[기본]` FR/NFR에 실행된 테스트가 1건 이상 연결되어 있다.
- “미실행” 항목은 통과로 계산하지 않는다.

## 7. 결함 심각도

| 등급 | 정의 | 예시 |
| --- | --- | --- |
| `S1` 치명 | 개인정보 노출·데이터 파괴·안전 문제 또는 핵심 흐름 전체 불가 | `DeviceMembership` 없는 다른 기기 영상 재생, 이동 카메라 비상 정지 실패 |
| `S2` 높음 | 우회 수단 없는 기본 기능 실패 | 웃음 영상 미생성, 업로드 유실, 최초 등록 불가 |
| `S3` 보통 | 우회 가능한 기능 오류 또는 부분 오동작 | 필터 불일치, 자동 재연결 실패지만 수동 재시도 가능 |
| `S4` 낮음 | 표현·문구·경미한 사용성 문제 | 정렬 아이콘, 오류 문구 오탈자 |

## 10. 실행 및 증거 수집 규칙

1. 테스트 시작 전에 결과서의 빌드, 커밋, 환경, 모델 버전과 실행자를 기록한다.
2. 한 테스트 케이스의 실제 결과는 실행한 사실과 증거가 있을 때만 `통과`, `실패`, `차단`, `해당 없음`으로 변경한다.
3. 로그에는 비밀번호, 전체 JWT, 제품 코드, 서명 URL 쿼리 문자열을 마스킹한다.
4. 영상 정확성은 육안만으로 판정하지 않고 원본 타임코드와 `ffprobe` 결과를 함께 보존한다.
5. 보안 테스트는 현재 사용자에게 `DeviceMembership`이 없는 별도 기기 데이터를 사용하고 실제 사용자 영상을 사용하지 않는다.
6. 장애 테스트 후 네트워크, 저장소 정책, 시간 설정 및 기기 상태를 원복한다.
7. 실패 시 결함 ID, 심각도, 재현 절차, 로그/스크린샷, 담당자와 재시험 결과를 연결한다.
