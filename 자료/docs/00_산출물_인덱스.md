## 4. 현재 사실 상태

| 항목 | 상태 | 갱신 조건 |
| --- | --- | --- |
| 애플리케이션 코드 | 미구현 | `backend/`, `mobile/`, `iot/`, `ai/` 코드 생성 후 갱신 |
| 테스트 실행 결과 | 전부 미실행 | 커밋·환경·담당자·증적과 함께 결과서 갱신 |
| 서비스 URL | 미배포 | 운영 또는 시연 서버 배포 후 기록 |
| 사용자 테스트 계정 | 미생성 | 통합 테스트 직전 비밀 채널로 배포 |
| 시스템 관리자 계정 | 해당 없음 | MVP는 `OWNER/MEMBER` 역할만 제공 |
| 호출어 엔진 | 확정 필요 | YAMNet과 별도 Keyword Spotting 검증 후 기록 |
| 객체 저장소 | MinIO 확정 | 배포 환경에서 AWS S3 미제공, EC2 위 Docker로 운영 |

## 5. 완료 후 반드시 갱신할 문서

1. API 구현이 바뀌면 OpenAPI, 화면–API 매핑과 추적성 매트릭스를 함께 수정한다.
2. DB 구조가 바뀌면 ERD, 데이터 사전과 `schema.sql`을 함께 수정한다.
3. 테스트를 실행하면 결과서에 커밋, 환경, 담당자, 실제 결과와 증적 경로를 기록한다.
4. 배포 후 서비스 URL, API 문서 URL, 테스트 계정과 롤백 기준을 갱신한다.
5. 심화 기능을 착수하면 개인정보 동의·저장 정책과 해당 테스트를 먼저 활성화한다.
