# 웃음·연속 박수 탐지 모델 비교 설계

## 1. 목적

현재 서비스는 YAMNet을 사용해 웃음과 연속 박수 이벤트를 감지한다. 이번
비교의 목적은 단순히 더 최신인 모델을 고르는 것이 아니라, Jetson Orin Nano의
실제 실행 조건에서 오탐을 충분히 억제하면서 웃음과 연속 박수를 놓치지 않는
모델을 찾는 것이다.

비교 대상은 다음 세 가지다.

- YAMNet TFLite
- EfficientAT MN10
- PANNs CNN10

세 모델은 모두 AudioSet 계열 클래스 체계를 사용한다. 따라서 AudioSet 원본을
최종 평가 세트로 다시 사용하지 않고, 직접 수집 데이터와 ESC-50으로 일반화
성능을 확인한다.

## 2. 데이터셋 구성

### 2.1 직접 수집 데이터

validation 60개와 test 60개를 각각 별도의 녹음 세션에서 수집한다. 모든
클립은 10초, mono PCM WAV, 48 kHz이며 장치와 마이크 위치를 고정한다.

| 상황 | validation | test | 이벤트 라벨 |
| --- | ---: | ---: | --- |
| 웃음 단독 | 10 | 10 | LAUGHTER |
| 연속 박수 | 10 | 10 | CLAP |
| 웃음+박수 | 10 | 10 | LAUGHTER, CLAP |
| 대화 | 10 | 10 | 없음 |
| 단발 박수·충격음 | 10 | 10 | 없음 |
| 음악·TV·생활 소음 | 10 | 10 | 없음 |

참가자는 최대 세 명까지 포함하며 거리와 인원 조합을 반복해 한 사람의 음색이나
한 위치에만 맞는 결과를 피한다. validation은 임계값 선택에만 사용하고 test는
임계값을 고정한 뒤 한 번 평가한다. 직접 녹음은 청취 검수 후에만 `verified`로
변경한다.

### 2.2 60분 연속 음성

오탐 이벤트/시간을 측정하기 위해 목표 이벤트가 없는 음성을 총 60분 수집한다.

- 조용한 사무실 15분
- 웃음 없는 대화 15분
- 웃음·박수 장면이 없는 TV 또는 음악 15분
- 키보드·의자·발걸음·단발 충격음 15분

클립 단위 오탐과 별도로 실제 서비스와 같은 연속 양성 창 및 12초 쿨다운을
재생해 시간당 거짓 이벤트 수를 계산한다.

### 2.3 외부 일반화 데이터

ESC-50 v2.0.0의 고정 커밋을 사용한다. 전체 2,000개 중 `laughing` 40개는
LAUGHTER 양성, `clapping` 40개는 CLAP 양성, 나머지 1,920개는 두 이벤트의
음성으로 사용한다. 원본은 Jetson에만 저장하며 저장소에는 URL, 커밋,
체크섬, 라이선스와 결과만 남긴다.

ESC-50는 CC BY-NC 3.0이므로 이번 비상업적 교육 프로젝트의 평가 목적으로만
사용한다. 공식 메타데이터 라벨을 사용하되 대표 실패 샘플은 결과 분석 때 직접
청취한다.

## 3. 공정한 모델 비교 방법

모든 모델은 같은 클립 순서와 같은 validation/test 분할을 사용한다. 다만 입력
길이를 강제로 같게 만들지 않고, 각 모델이 학습·공식 추론 예제에서 전제로 하는
시간 문맥을 사용한다. 입력 창이 긴 모델은 반응 조건이 더 불리할 수 있으므로
입력 창, 갱신 hop, 연속 양성 창 수와 최소 판정 구간을 결과에 함께 기록한다.

| 모델 | 입력 창 | 갱신 hop | 연속 양성 창 | 최소 판정 구간 | 근거 |
| --- | ---: | ---: | ---: | ---: | --- |
| YAMNet TFLite | 0.975초 | 0.4875초 | 2 | 1.4625초 | 고정 입력 크기와 기존 운영 연속 판정 |
| EfficientAT MN10 | 10초 | 2.5초 | 1 | 10초 | 공식 windowed inference 기본 설정 |
| PANNs CNN10 | 2초 | 1초 | 2 | 3초 | 공식 sound event detection 예제의 연속 2초 구간 |

초기 부분 실행에서는 세 모델에 모두 YAMNet의 0.975초 입력을 적용했다. 이때
EfficientAT는 웃음·박수·대화 샘플 구분 없이 524~525개 클래스 점수가 1.0으로
포화됐고, validation과 test 전부를 양성으로 예측했다. FP16과 FP32에서 같은
현상이 발생했지만 10초 입력에서는 정상적인 점수 분포가 복원되어, 체크포인트나
정밀도 문제가 아니라 입력 문맥 불일치로 판단했다. 해당 부분 배치
`audio-accuracy-comparison-20260803T153735Z`는 최종 비교에서 제외하고 진단
기록으로만 보존한다.

한 번의 추론에서 웃음 및 박수 클래스 점수를 모두 저장한다. 각 이벤트는
validation에서 별도 임계값을 선택하며 최소 Recall 0.85를 만족하는 후보 중
거짓 양성 수가 가장 작은 임계값을 우선한다.

test에서는 다음 지표를 기록한다.

- 이벤트별 Precision, Recall, F1
- 조건별 FP, FN과 실패 샘플 목록
- 연속 음성의 시간당 거짓 이벤트 수
- 평균 및 P95 추론 지연시간
- GPU 최대 사용률, RAM 최대 사용량, 최고 온도와 최고 전력
- 세 번 반복한 결과의 평균과 편차

test 2,064개는 한 덩어리의 수치로만 평가하지 않고 다음 세 코호트로 분리한다.
특히 60분 연속 음성의 오탐률이 ESC-50의 짧은 음성 1,920개에 의해 희석되지
않도록 각 코호트의 시간당 거짓 이벤트 수를 별도로 계산한다.

| 평가 코호트 | 구성 | 판단 목적 |
| --- | --- | --- |
| `localDirect` | 직접 수집 test 60개 | 실제 사무실 조건의 웃음·박수 Recall과 F1 |
| `continuousNegative` | 목표 이벤트가 없는 15분 음성 4개 | 실제 운영 형태의 FP/hour |
| `externalGeneralization` | ESC-50 2,000개 | 낯선 소리에 대한 일반화와 실패 유형 |

## 4. 서비스 적합성 기준

1차 통과 기준은 `localDirect`에서 두 이벤트 모두 Recall 0.85 이상,
`continuousNegative`에서 두 이벤트 모두 시간당 거짓 이벤트 1회 이하다.
여러 모델이 통과하면 연속 음성 오탐이 적은 모델, 직접 수집 Macro F1이 높은
모델, 직접 수집 최소 Recall이 높은 모델, ESC-50 Macro F1이 높은 모델,
입력 문맥이 짧은 모델, P95 지연시간이 짧은 모델 순서로 비교한다. 추론
지연시간만 짧아도 입력 창이 길면 사용자가 체감하는 반응은 늦을 수 있기
때문이다. ESC-50은 서비스 환경 자체를 대표하지 않으므로 단독 통과 기준으로
사용하지 않는다.

이 기준을 통과한 모델도 바로 운영 모델로 확정하지 않는다. YOLOv8n TensorRT
FP16과 동시에 실행했을 때 자원 경합과 프레임 처리 성능을 확인하고, 실제 앱의
이벤트 영상 생성·업로드·표시까지 종단 검증한 뒤 최종 전환한다.

## 5. 실행 안전과 개인정보

수집과 단독 벤치마크 중에는 앱 연결, 1분 단위 상시 녹화, 이벤트 탐지·업로드,
서보 제어를 중지한다. 로컬 RTSP의 오디오 입력만 유지한다. 종료 후 이전에
실행 중이던 서비스를 복원하되 서보는 배터리 상태를 사람이 확인하기 전에는
자동으로 다시 시작하지 않는다.

음성 원본과 사람 목소리는 Git에 커밋하지 않는다. `dataset.json`에는 로컬 경로,
SHA-256, 분할, 조건, 라벨, 검수 상태만 기록한다.

## 6. 결과물

- 모델별 원시 window 예측 JSONL
- 이벤트별 accuracy `summary.json`
- 실시간 `progress.json`과 `tegrastats` 로그
- 세 모델 비교 JSON, CSV, Markdown 보고서
- 대시보드의 직접 수집 F1·Recall, 연속 음성 FP/hour, ESC-50 F1·Recall,
  입력 창·hop·최소 판정 구간, P95 지연시간 화면
- 발표용 모델 선택 근거와 실패 사례 목록

대시보드는 가장 최근 오디오 comparison ID에 속한 완료 결과만 카드에 집계한다.
중단됐거나 진단용으로 보존한 이전 배치가 새 최종 결과에 섞이지 않도록 한다.
