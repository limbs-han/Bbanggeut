# 편집·AI 결과물 제품 결정안

> 상태: 편집 화면 UI **미확정**, 일반 편집 방향(로컬 처리)만 확정, AI 편집·생성 기능 미확정
> 원칙: 기능·모델·개인정보·보관 정책을 결정하기 전에는 백엔드 API와 DB 스키마를 만들지 않는다.
> 주제 전환(2026-07-21): 홈캠으로 전환하면서 영상 편집은 서비스의 주축이 아니라 저장된 순간을 다듬는 부가 기능이다. 편집 화면 구성은 확정본이 아니며, 아래 라이브러리 검토 결과에 따라 프레임워크·화면을 재정할 수 있다.

## 1. 현재 확정 범위

| 결과물 | MVP 방식 | 서버 저장 |
| --- | --- | --- |
| 일반 편집 도구 | 앱에서 구간 자르기, 음량, 자막·텍스트, 간단한 필터와 내보내기 | 안 함 |
| AI 편집 도구 | 후보 검증 후 1개 선택 | 미정 |
| 새로운 AI 결과물 | 후보 검증 후 1개 선택 | 미정 |

일반 편집은 기존 `POST /api/videos/{videoId}/download-url`만 사용한다. 앱이 원본을 임시 다운로드하고 로컬에서 결과를 만든 뒤 사용자 단말이나 공유 대상으로 내보낸다. 편집 구간, 프로젝트, 결과 파일을 서버에 보내지 않는다.

## 2. AI 편집 후보

| 후보 | 사용자 가치 | 입력·출력 | 구현 난도 | 권장 |
| --- | --- | --- | ---: | --- |
| 하이라이트 자동 추출 | 긴 영상에서 웃음·사람·움직임이 큰 구간을 자동 선택 | 원본 영상 → 짧은 클립 후보와 타임라인 | 중 | 1순위 |
| 자동 세로 리프레임 | 사람들의 중앙을 따라 9:16 영상 생성 | 원본+사람 bbox → 세로 영상 | 중 | 1순위와 결합 가능 |
| 자동 자막·제목 | 음성을 자막으로 바꾸고 제목을 제안 | 오디오 → 자막 파일·텍스트 레이어 | 중 | 2순위 |
| 음성 정리 | 잡음 감소·음량 평준화 | 오디오 → 개선 오디오 | 낮음~중 | 편집 보조 |
| 분위기 템플릿 | 장면에 맞는 전환·음악·색감을 추천 | 특징량 → 편집 파라미터 | 중~높음 | 후순위 |

MVP 권장 조합은 **하이라이트 자동 추출 + 사람 중심 세로 리프레임**이다. 이미 보유한 웃음 이벤트와 YOLO 사람 bbox를 재사용할 수 있고, 결과가 실패해도 사용자가 타임라인에서 직접 수정할 수 있다.

## 3. 새로운 AI 결과물 후보

| 후보 | 산출물 | 장점 | 주요 위험 | 권장 |
| --- | --- | --- | --- | --- |
| 4컷 추억 만화 | 대표 프레임 4장+말풍선 | 데모가 명확하고 정지 이미지라 비용·시간 통제가 쉬움 | 얼굴 변형, 대사 환각 | 1순위 |
| 추억 하이라이트 영상 | 대표 장면+제목+전환+음악 | 기존 영상과 자연스럽게 연결 | 음악 저작권, 렌더링 시간 | 2순위 |
| 그림책·스토리 카드 | 여러 장의 일러스트+짧은 문장 | 가족 콘텐츠로 차별화 | 아동·얼굴 개인정보, 사실 왜곡 | 2순위 |
| 완전 생성 애니메이션 | 영상 기반 새 스타일 영상 | 시각적 임팩트 | GPU 비용·지연·일관성·초상권 | 후순위 |

MVP 권장은 **4컷 추억 만화**다. 사용자가 대표 프레임을 확인·교체하고, 생성 대사를 편집한 뒤에만 내보내도록 한다. 원본 얼굴과 다른 결과가 나올 수 있음을 명시한다.

## 4. 백엔드 구현 전 결정 게이트

아래가 모두 결정되기 전에는 `/ai-edits`, `/generations` 같은 API나 작업 테이블을 추가하지 않는다.

1. 정확히 한 가지 사용자 입력과 한 가지 결과 형식을 선택한다.
2. 온디바이스, 자체 GPU 서버, 외부 API 중 처리 위치를 선택한다.
3. 원본 전체를 전송할지 사용자가 고른 프레임·구간만 전송할지 정한다.
4. 결과를 단말에만 둘지, 만료 임시 객체로 전달할지, 서버에 영구 보관할지 정한다.
5. 얼굴·음성·아동 영상 동의, 외부 전송, 모델 학습 미사용 조건을 확정한다.
6. 최대 입력 길이·크기, 목표 지연, 동시 작업 수, 월 비용 상한을 정한다.
7. 취소·재시도·실패·부적절한 결과 신고와 삭제 기한을 정한다.

## 5. 선택에 따른 백엔드 영향

| 처리·보관 방식 | 백엔드 변경 |
| --- | --- |
| 완전 온디바이스·단말 저장 | 기존 원본 다운로드 URL 외 신규 영상 저장 API 없음 |
| 서버 처리·결과 임시 전달 | 생성 작업 상태, 입력 권한 스냅샷, 만료 임시 객체, 취소·삭제 worker 필요 |
| 서버 처리·결과 영구 저장 | 위 항목에 더해 결과 자산 모델, 보관 정책, 사용량·쿼터, 멤버십 인가, 감사 로그 필요 |
| 외부 AI API | 명시적 동의, 데이터 처리 지역·보존·학습 미사용 계약, 공급자 장애·비용 제한 필요 |

현재 기본안은 개인정보와 백엔드 범위를 최소화하는 **온디바이스 또는 단말 저장**이다. 서버 처리로 바꿀 때는 이 문서의 결정 게이트를 먼저 닫고 OpenAPI·ERD·보안·테스트 문서를 함께 갱신한다.

## 6. 로컬 영상 편집 라이브러리 검토 (프레임워크별)

편집은 서버 없이 앱 내에서 처리하므로, 프레임워크에 따라 타임라인 편집 SDK의 라이선스·비용이 달라진다. 홈캠 전환으로 편집이 부가 기능이 된 만큼 **유료 SDK 종속을 피하고 오픈소스 + FFmpeg 조합**을 우선한다.

### 6.1 Flutter (현재 앱)

| 옵션 | 라이선스·비용 | 비고 |
| --- | --- | --- |
| VideoEditor SDK / PESDK (img.ly) | **상용 유료(연 구독, 견적형)** | 완성형 타임라인 UI. 무료 아님 |
| `ffmpeg_kit_flutter` | LGPL/GPL 빌드 선택 가능(무료) | 2025년 초 공식 retire·바이너리 배포 중단 → 커뮤니티 포크 유지보수 필요 |
| `video_editor`(패키지) + `ffmpeg` | 무료(오픈소스) | 트림·커버 중심. 자막·오버레이·PIP는 직접 구현 |
| `video_player`+`flutter_ffmpeg` 자체 조합 | 무료 | UI를 직접 만들어야 함 |

즉, "Flutter 편집 라이브러리가 유료"라는 것은 **완성형 UI SDK(img.ly 계열)**를 말한다. FFmpeg 기반 무료 경로는 있으나 UI를 직접 구현해야 하고, `ffmpeg_kit_flutter` retire로 유지보수 리스크가 있다.

### 6.2 React Native

| 옵션 | 라이선스·비용 | 비고 |
| --- | --- | --- |
| `react-native-video` | MIT(무료) | 재생 전용. 편집 아님 |
| `ffmpeg-kit-react-native` | 무료 | Flutter와 동일하게 retire 이슈 → 포크 필요 |
| `react-native-video-trim`, `react-native-video-editor` | MIT(무료) | 트림 위주, 기능 제한 |
| Banuba / img.ly RN SDK | **상용 유료** | 완성형 UI. 무료 아님 |
| Shotstack 등 클라우드 렌더 API | 종량제(유료) | 서버 렌더 방식이라 로컬 편집 원칙과 상충 |

### 6.3 React (웹)

| 옵션 | 라이선스·비용 | 비고 |
| --- | --- | --- |
| `ffmpeg.wasm` | 무료(오픈소스) | 브라우저 내 트랜스코딩. 모바일 성능 한계 |
| Remotion | **개인·소규모 무료, 회사 규모별 유료 라이선스** | 코드로 영상 생성. 실시간 편집 UI는 아님 |
| Etro, `react-video-editor` 등 | 무료(오픈소스) | 성숙도·유지보수 편차 큼 |
| Creatomate / Shotstack | 유료(클라우드) | 서버 렌더 |

### 6.4 결론

- **완성형 타임라인 UI를 즉시 붙이려면 어느 프레임워크든 상용 SDK(img.ly·Banuba 등)가 사실상 유일하며 모두 유료**다. 무료 완성형은 없다.
- **무료로 가려면 FFmpeg(Flutter `ffmpeg_kit` 포크 / RN `ffmpeg-kit` 포크 / 웹 `ffmpeg.wasm`) + 자체 타임라인 UI** 조합이 공통 경로다. 프레임워크를 바꿔도 "무료 = 직접 구현" 구조는 동일하다.
- 홈캠에서 편집은 부가 기능이므로 MVP는 **트림·자막·간단 필터·내보내기 수준으로 축소**하고, `video_editor` + FFmpeg 무료 경로로 시작하는 것을 권장한다. 프레임워크 이전(React Native/웹)만으로 유료 문제가 사라지지는 않는다.
