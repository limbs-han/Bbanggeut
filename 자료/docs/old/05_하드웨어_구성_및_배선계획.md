# 윌리엄 제임스 하드웨어 구성 및 배선 계획

> 문서 상태: 설계·조립 계획  
> 적용 기간: 7월 20일 ~ 7월 31일  
> 주 담당: IoT 유지호 / 협업: AI 이재준, PM 사지한  
> **주의:** 아래 연결은 논리 계획이다. 실제 핀 번호는 보드 리비전·핀맵·사용 라이브러리를 확인한 뒤 배선표에 확정한다.

## 1. 범위와 우선순위

- **[기본·필수]** 카메라, USB 마이크, 터치 센서, 프라이버시 LED, 7" HDMI LCD(등록 코드 표시), 순환 녹화, 안정적인 전원·냉각·저장장치
- **[기본]** Jetson Orin Nano의 AI·영상 처리와 Raspberry Pi 5의 GPIO 제어
- **[심화]** I2C LCD, 팬·틸트 서보, 3D 프린팅 프레임, 외장 SSD
- **[심화·선택]** 오린카, DC 모터, 초음파, LiDAR, 온습도 센서

MVP의 핵심은 고정형 카메라에서 웃음·호출·터치 이전 장면을 저장하는 것이다. 이동형 차량과 환경 센서는 핵심 기능이 안정화되기 전에는 연결하지 않는다.

## 4. 기본 배선 계획

### 4.1 USB 장치

| 연결 | 대상 | 검증 |
| --- | --- | --- |
| USB 카메라 → Jetson USB 3.x | 영상 입력 | 지원 포맷, 해상도, FPS, 30분 연속 캡처 |
| USB 마이크 → Jetson USB | 음성 입력 | ALSA 장치명, 모노·스테레오, 16kHz 변환, 입력 레벨 |
| Jetson ↔ 네트워크 | 서버·Pi 통신 | 고정 호스트명 또는 예약 IP, 재부팅 후 자동 연결 |
| Pi ↔ 네트워크 | Jetson·서버 통신 | 로컬 지연·패킷 손실, 시간 동기화 |

Linux 장치 번호 <code>/dev/video0</code>, <code>hw:0</code>는 재부팅 후 바뀔 수 있다. USB VID/PID, <code>/dev/v4l/by-id</code> 또는 ALSA 장치명을 기준으로 고정 매핑한다.

### 4.2 TTP223B 터치 센서

| 센서 단자 | 연결 계획 | 조건 |
| --- | --- | --- |
| VCC | 보드 3.3V | 모듈 사양 확인 후 3.3V 사용 |
| GND | 보드 GND | 공통 접지 |
| OUT | 선택한 디지털 입력 GPIO | 내부 풀업·풀다운, Active High 여부를 코드와 일치 |

- 짧은 터치: **[기본]** 최근 2분 영상 저장
- 긴 터치: **[기본]** 최초 기기 등록 모드 진입
- 길이 기준과 디바운스 시간은 **[미확정]**이며 PM·IoT가 확정한다.
- 긴 터치와 짧은 터치가 동시에 실행되지 않도록 버튼 상태 머신을 둔다.

### 4.3 프라이버시 LED

~~~mermaid
flowchart LR
    GPIO["3.3V GPIO 출력"] --> R["직렬 저항<br/>초기안 220Ω급"]
    R --> A["LED 애노드"]
    K["LED 캐소드"] --> GND["GND"]
~~~

- 단일 LED 기본 패턴은 다음과 같이 고정한다.

| 실제 기기 상태 | 단일 LED 기본 패턴 | 2색 LED 대안 |
| --- | --- | --- |
| 카메라 읽기 중지·순환 녹화 중지·원격 LIVE 중지 확인 | 소등 | 두 색 모두 소등 |
| 카메라 프레임 읽기 또는 순환 녹화 중, 원격 LIVE 없음 | 상시 점등 | 녹화 색상 상시 점등 |
| 원격 LIVE publisher 송출 중 | 1Hz 점멸(500ms ON/500ms OFF) | 녹화 색상 상시 점등 + 라이브 색상 1Hz 점멸 |
| 카메라·publisher 상태 확인 불가 또는 LED 제어 통신 오류 | 촬영 프로세스가 살아 있다면 1Hz 점멸을 유지하는 fail-safe | 녹화 색상 점등 + 라이브 색상 1Hz 점멸 |

- 앱 연결 여부와 무관하게 카메라 프레임을 실제로 읽거나 로컬 순환 버퍼가 동작하면 녹화 상태로 표시한다. 원격 LIVE 점멸은 `START_STREAM` 요청 수신만이 아니라 기기 live publisher가 실제 송출 중인 상태와 연동한다.
- 단일 LED의 500ms OFF 구간은 LIVE를 구분하기 위한 점멸 패턴이다. 촬영 중 LED를 계속 꺼 두는 상태와 사용자 설정은 허용하지 않는다.
- LED 제어는 서버 상태만 믿지 않고 Jetson의 `cameraReadActive`·`circularRecordingActive`와 live publisher의 `remoteLiveActive`를 로컬로 받아 결정한다. 상태 채널이 끊겼는데 촬영 프로세스가 살아 있으면 가장 눈에 띄는 LIVE 패턴으로 fail-safe 처리한다.
- GPIO 허용 전류와 LED 순방향 전압을 확인해 저항값을 계산한다. 보드 핀당·전체 전류 한도를 넘기지 않는다.
- **[심화·권장]** 카메라 전원 또는 하드웨어 enable 신호와 연동해 소프트웨어 오류로 LED만 꺼진 채 촬영되는 상황을 줄인다.
- 사용자에게 녹화 상태를 숨기는 LED 끄기 옵션은 제공하지 않는다.
- 패턴은 실기기에서 카메라 시작·중지, 순환 녹화, LIVE 시작·종료, publisher 강제 종료, Pi↔Jetson 상태 통신 단절, 재부팅 순서로 시험한다. 휴대전화 영상 또는 로직 로그로 1Hz 주기와 실제 상태 전환 시각을 함께 기록한다.

## 5. 심화 배선 계획

### 5.1 PCA9685와 SG-90

~~~mermaid
flowchart LR
    PI["Raspberry Pi 5<br/>3.3V I2C"] -->|"SDA·SCL·GND"| PCA["PCA9685"]
    PSU["별도 5V 서보 전원"] -->|"V+·GND"| PCA
    PCA -->|"PWM CH0"| PAN["팬 서보"]
    PCA -->|"PWM CH1"| TILT["틸트 서보"]
    PI ---|"공통 GND"| PSU
~~~

- Pi의 3.3V는 PCA9685 로직 전원에만 사용하고 서보 V+는 별도 5V 전원에서 공급한다.
- 보드·PCA9685·외부 전원의 GND는 공통으로 연결한다.
- 서보 정지각과 기계적 최대·최소각을 먼저 측정하고 소프트웨어 제한을 둔다.
- 전원 투입 시 갑작스러운 회전으로 케이블이 끼이지 않도록 카메라 없이 초기 시험한다.
- 팬·틸트 움직임 중 영상 흔들림이 크면 이동 완료 후 짧은 안정화 시간을 두고 촬영한다.

### 5.2 HC-SR04

- Trig 입력은 3.3V GPIO 출력으로 제어 가능 여부를 모듈 사양으로 확인한다.
- Echo가 5V로 출력되는 일반 모듈이면 GPIO에 직접 연결하지 않는다.
- Echo에는 계산된 저항 분압기 또는 양방향 레벨 시프터를 사용해 3.3V 이하로 낮춘다.
- 센서 추가는 **[심화·선택]**이며 고정형 MVP 배선과 분리한다.

### 5.3 DC 모터

~~~mermaid
flowchart LR
    BOARD["Pi 또는 Jetson<br/>PWM·DIR 신호"] --> DRIVER["H-브리지 모터 드라이버"]
    BAT["모터용 전원"] --> DRIVER
    DRIVER --> MOTOR["DC 모터"]
    BOARD ---|"공통 GND"| BAT
~~~

- 모터를 GPIO, PCA9685 출력, 브레드보드 전원 레일에 직접 연결하지 않는다.
- 역기전력 보호가 포함된 모터 드라이버를 사용한다.
- 로직 전원과 모터 전원 규격, 공통 접지, 정지 시 fail-safe를 확인한다.
- 비상 정지 또는 전원 차단 수단을 손이 닿는 위치에 둔다.

## 6. 전원·열·저장 안전

| 위험 | 기본 통제 |
| --- | --- |
| 보드 저전압·재부팅 | Jetson·Pi 각각 정격 전원 사용, 전원 경고 로그 확인 |
| 서보 순간 전류 | 별도 5V 전원, 공통 접지, 보드 5V 핀 직결 금지 |
| GPIO 5V 유입 | 모든 센서 출력 전압 측정, 필요 시 분압·레벨 시프터 |
| 과열·스로틀링 | 방열판·팬 장착, 30분 이상 AI·녹화 부하에서 온도 기록 |
| microSD 마모 | 짧은 세그먼트 자동 삭제, 로그 로테이션, [심화] SSD 캐시 |
| 전원 중 파일 손상 | 임시 확장자에 기록 후 원자적 이름 변경, 주기적 flush, 정상 종료 절차 |
| USB 전력·대역폭 부족 | 카메라·마이크 동시 부하 시험, 필요 시 전원형 USB 허브 |
| 케이블 빠짐 | 스트레인 릴리프, 케이블 타이, 커넥터 방향 라벨 |

전원이 연결된 상태에서 GPIO 배선을 변경하지 않는다. 멀티미터로 전압·극성·연속성을 확인한 뒤 장치를 연결한다.

## 7. 3D 프린팅 계획

### 7.1 기본과 심화 구분

- **[기본]** 기존 삼각대·클램프·고정 거치대를 사용한다. 3D 프린터는 MVP 필수 조건이 아니다.
- **[심화]** SG-90 두 개를 이용한 팬·틸트 프레임과 카메라 하우징을 출력한다.
- **[심화]** 보드 케이스는 통풍구, 카메라·마이크 시야·음향 구멍, LED 노출, 케이블 굽힘 반경을 포함한다.

### 7.3 출력·조립 기준

- STL과 수정 가능한 STEP 또는 원본 CAD 파일을 함께 보관한다.
- 서보 축에 과도한 하중이 걸리지 않도록 카메라 무게 중심을 축 가까이에 둔다.
- 최대 회전에서도 USB 케이블이 당겨지거나 꼬이지 않아야 한다.
- 1차 저해상도 시험 출력 → 간섭 확인 → 최종 출력 순서로 진행한다.
- 프레임에 손가락이 끼일 수 있는 지점을 표시하고 이동 속도·각도를 제한한다.

## 8. 조립 및 검증 순서

### 8.1 기본 조립

1. Jetson·Pi 냉각 장치와 정격 전원을 단독으로 점검한다.
2. Jetson에 카메라만 연결해 30분 영상을 저장한다.
3. USB 마이크를 연결해 웃음·대화·TV 소리 샘플의 레벨을 확인한다.
4. 전원을 끈 상태에서 Pi에 터치 센서와 LED를 연결한다.
5. 단독 GPIO 테스트 후 카메라 프로세스와 LED 상태를 연동한다.
6. 두 보드 시간 동기화와 로컬 이벤트 왕복을 확인한다.
7. 순환 녹화·터치 저장·업로드를 통합한다.
8. 케이블을 고정하고 핀·전원 라벨을 부착한다.

### 8.2 심화 조립

1. 외부 전원과 PCA9685만 연결해 전압을 측정한다.
2. 카메라 없이 서보 한 축씩 중앙값·한계각을 확인한다.
3. 시험 출력 프레임을 조립하고 케이블 간섭을 확인한다.
4. 카메라를 장착하고 저속 팬·틸트를 시험한다.
5. 앱 원격 제어, 범위 제한, 연결 해제 시 정지 동작을 확인한다.
