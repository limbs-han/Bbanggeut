# 윌리엄 제임스 배포·운영 체크리스트

> 문서 상태: 배포 계획·런북  
> 현재 상태: **미배포 / 실제 URL·계정·시험 결과 미입력**  
> 배포 주 담당: 백엔드 박찬형 / 승인: PM 사지한  
> 이 문서의 명령은 목표 구조의 예시다. 실제 저장소 경로·서비스명·서버 OS에 맞춰 검토 후 실행한다.

> **현재 데모 보안 경계:** CI/CD는 비민감 demo workflow 골격뿐이다. Mosquitto는 loopback의 평문 1883·공유 개발 계정이며 기기별 topic ACL이 없고, MinIO에는 KMS/SSE가 없다. production·실제 사용자·실기기 자격 증명·사생활 영상에는 사용할 수 없으며, MQTTS·기기별 ACL·저장 암호화 후 별도 운영 승인이 필요하다.

## 1. 배포 범위

### 1.1 [기본]

- Flutter Android 앱
- Spring Boot 단일 API 서버
- PostgreSQL
- MinIO 또는 AWS S3 비공개 객체 저장소
- Mosquitto MQTT
- Nginx TLS 리버스 프록시
- MediaMTX 등 기기 ingest를 HLS로 remux·fan-out할 별도 미디어 계층 후보
- FFmpeg 영상 편집 모듈
- Jetson Orin Nano의 AI·영상·업로드 서비스
- Raspberry Pi 5의 터치·LED·로컬 제어 서비스
- GitHub Actions 기반 테스트·이미지 빌드·배포

### 1.2 [심화]

- Firebase Cloud Messaging
- WebRTC
- 별도 비동기 작업 큐·워커
- 기기별 암호화 키
- 팬·틸트 원격 제어
- 생성형 콘텐츠 서비스

Jenkins는 별도 서버 운영 부담 때문에 MVP에서 사용하지 않는다. GitHub Actions와 Docker Compose를 기본으로 한다.

~~~mermaid
flowchart LR

    GHA --> REG["Container Registry"]

        NGINX --> API

        API --> MINIO
        API --> MQTT

    end

    APP["Flutter 앱"] <-->|"HTTPS"| NGINX
~~~

Nginx가 MQTT TLS를 직접 종료하지 않는 구성이라면 Mosquitto의 TLS 포트를 별도 공개하고 방화벽과 인증을 적용한다. 구성 선택은 배포 전 확정한다.

| 환경 | 목적 | 데이터 | 접근 | 저장소 | 상태 |
| --- | --- | --- | --- | --- | --- |
| local | 개인 개발·단위 시험 | 가짜 계정·짧은 테스트 영상 | 개발 PC | Docker MinIO | 계획 |

local·integration과 demo의 DB, 버킷, JWT 키, 기기 자격 증명을 공유하지 않는다.

### 4.2 테스트 계정

실제 비밀번호는 이 문서나 Git에 기록하지 않고 팀의 비밀 공유 채널로 전달한다.

| 용도 | ID·이메일 | 비밀번호 | 준비 상태 |
| --- | --- | --- | --- |
| 기기 소유자 OWNER | <code>배포 후 입력</code> | <code>별도 비밀 채널 전달</code> | 미생성 |
| 일반 기기 구성원 MEMBER | <code>배포 후 입력</code> | <code>별도 비밀 채널 전달</code> | 미생성 |
| `DeviceMembership` 없는 다른 기기 권한 차단 시험 | <code>배포 후 입력</code> | <code>별도 비밀 채널 전달</code> | 미생성 |
| 시스템 관리자 | 해당 없음 — MVP에 별도 시스템 관리자 사용자 기능을 두지 않음 | 해당 없음 | 정책 확인 필요 |
| 테스트 기기 ID | <code>프로비저닝 후 입력</code> | 기기별 자격 증명은 문서에 기재 금지 | 미등록 |

## 6. 환경 변수·비밀정보 목록

변수 이름은 실제 구현과 동기화한다. 아래 값은 입력하지 않는다.

| 범주 | 예시 변수 | 비밀 여부 | 요구사항 |
| --- | --- | --- | --- |
| 애플리케이션 | <code>SPRING_PROFILES_ACTIVE</code> | 아니오 | local/integration/demo 분리 |
| DB | <code>DB_URL</code>, <code>DB_USER</code>, <code>DB_PASSWORD</code> | 비밀번호는 비밀 | 최소 권한 앱 계정 |
| JWT | <code>JWT_SIGNING_KEY</code>, token TTL 설정 | 키는 비밀 | 충분한 임의성, 회전 계획 |
| 저장소 | <code>S3_ENDPOINT</code>, <code>S3_BUCKET</code>, <code>S3_ACCESS_KEY</code>, <code>S3_SECRET_KEY</code> | key는 비밀 | public access 차단, 전용 계정 |
| MQTT | <code>MQTT_URL</code>, <code>MQTT_USER</code>, <code>MQTT_PASSWORD</code> | 자격 증명은 비밀 | 익명 접속 금지, topic ACL |
| 라이브 세션 | <code>STREAM_HEARTBEAT_INTERVAL_SECONDS=15</code>, <code>STREAM_SESSION_TTL_SECONDS=45</code>, <code>STREAM_IDLE_TIMEOUT_SECONDS=60</code>, <code>STREAM_EDGE_HARD_TIMEOUT_SECONDS=120</code> | 아니오 | 마지막 활동부터 stop까지 최대 60초; 활성 시청 중 `hardExpiresAt`을 약 120초 뒤로 연장 |
| 미디어 계층 | <code>MEDIA_INGEST_URL</code>, <code>HLS_BASE_URL</code> | ingest 자격 증명은 비밀 | 기기 live publisher ingest와 HLS origin을 분리하고 무재인코딩 remux 확인 |
| CORS | <code>ALLOWED_ORIGINS</code> | 아니오 | 실제 origin만 허용 |
| 앱 미디어 라이브러리 | 지원 코덱, 임시 캐시 상한 | 아니오 | 기준 Android 실기기 인코딩·내보내기 확인 |
| 관측 | 로그 레벨, 오류 추적 DSN | DSN은 비밀 가능 | 영상 URL·토큰 마스킹 |
| 기기 | device ID, credential path, API·MQTT URL | credential은 비밀 | 장치별 발급, 최소 파일 권한 |
| FCM | service account | [심화] 비밀 | 앱에 서버 키 포함 금지 |

## 8. 서버 최초 준비 체크리스트

### 8.1 OS·네트워크

- [ ] 지원되는 64비트 Linux와 보안 업데이트
- [ ] 불필요한 inbound 포트 차단
- [ ] SSH 비밀번호 로그인 비활성화 검토, 키 기반 접근

### 8.2 Docker·볼륨

- [ ] Docker Engine·Compose 버전 기록
- [ ] 컨테이너가 root 이외 사용자로 실행 가능한지 확인

- [ ] 이전 릴리스 이미지 최소 1개 유지

| 포트·서비스 | 외부 공개 | 원칙 |

## 10. 객체 저장소 배포

- [ ] 버킷 이름과 환경 분리
- [ ] anonymous/public list·get·put 모두 차단
- [ ] 저장 암호화 활성화
- [ ] 앱 서버 전용 서비스 계정과 최소 권한
- [ ] IoT 업로드용 서명 URL이 특정 key·method·만료로 제한
- [ ] 앱 재생·다운로드 URL 만료를 1~5분 후보에서 확정
- [ ] CORS는 필요한 method·header·origin만 허용
- [ ] 최대 객체 크기와 지원 MIME·코덱 제한
- [ ] 불완전 multipart upload 자동 정리
- [ ] 원본·썸네일 삭제 연계 및 서버에 신규 편집본 객체가 생성되지 않음
- [ ] 보관 기간과 자동 삭제 작업
- [ ] 서명 URL과 secret key가 로그에 남지 않음

## 11. MQTT 배포

- [ ] 익명 접속 비활성화
- [ ] TLS 인증서와 호스트 검증
- [ ] 기기별 사용자 또는 인증서
- [ ] 기기가 자신의 topic만 publish·subscribe하도록 ACL
- [ ] 명령·상태 topic에 환경과 device ID 포함
- [ ] retained message가 민감한 명령·토큰을 보존하지 않음
- [ ] payload에 schemaVersion·eventId·timestamp 포함
- [ ] 중복·순서 역전·재연결 처리
- [ ] 라이브 명령은 단일 <code>{env}/wj/v2/devices/{deviceId}/commands</code> 토픽의 <code>START_STREAM</code>·<code>EXTEND_STREAM</code>·<code>STOP_STREAM</code>이며 ACK에 request/stream ID와 필요한 만료 시각 포함
- [ ] 다중 시청자여도 기기당 송출 시작은 한 번이며 중복 `START_STREAM/EXTEND_STREAM/STOP_STREAM` 명령이 멱등하게 처리됨

### 17.2 로그 원칙

- JSON 등 검색 가능한 구조와 UTC 시각, traceId, eventId를 사용한다.
- 비밀번호, JWT, refresh token, 등록 코드 원문, 기기 private key, 기기 초대 토큰, 서명 URL을 기록하지 않는다.
- 영상·음성 내용과 얼굴 프레임을 오류 로그에 첨부하지 않는다.
- 로그 크기·파일 수·보관 기간을 제한한다.
- 앱·API·IoT의 eventId로 한 영상 흐름을 추적할 수 있게 한다.

### 17.3 초기 경보 후보

임계값은 부하 시험 후 확정한다.

- API 5xx 또는 편집 FAILED 급증
- 저장소 업로드 실패·용량 한도 접근
- 기기 오프라인·재연결 반복
- 마지막 유효 heartbeat/DELETE부터 60초가 지났는데 edge 송출 지속, TTL 만료 뒤 60초를 추가 대기, 새 세션의 stop 예약 취소 실패, 마지막 `hardExpiresAt`에서 약 120초가 지나도 자체 종료하지 않음
- 첫 heartbeat 없는 PENDING이 createdAt+45초 뒤에도 active이거나 createdAt+60초 뒤에도 STOP되지 않음
- CLOSED/EXPIRED·권한 회수 후 새 HLS playlist/segment가 계속 200으로 전달됨
- 기기 하나에 H.264/AAC 인코더가 두 개 이상 실행되거나 HLS 재인코딩 감지

- 데이터 삭제·변조·migration 오류
- 앱의 핵심 영상 재생 불가
- 시청자 0명 stop deadline 또는 마지막 연장 기준 약 120초 `hardExpiresAt` 뒤에도 라이브 송출이 종료되지 않음
- 라이브 시작으로 순환 녹화가 중단되거나 별도 HLS 재인코딩으로 장비가 불안정해짐
- 기기 업데이트 후 순환 녹화·LED 불일치
- 5xx·재시작 루프가 smoke test 기준을 초과

### 18.2 서버 롤백

1. 신규 배포 트래픽을 중단한다.
2. PM과 팀에 영향 범위·시작 시각을 알린다.
3. 이전 불변 이미지 digest로 되돌린다.
4. DB migration이 backward compatible하지 않으면 사전 정의된 복구 절차를 실행한다.
5. health와 SMK-01·02·06·07·10·14를 우선 재시험한다.
6. 원인·데이터 영향·후속 조치를 기록한다.

### 18.3 기기 롤백

1. 카메라 서비스를 중지하고 LED 상태를 확인한다.
2. 이전 코드·모델 버전과 설정 체크섬으로 복원한다.
3. 대기 업로드 큐를 삭제하지 말고 호환 여부를 확인한다.
4. 터치 저장·이벤트 영상·재업로드를 시험한다.
5. Pi↔Jetson 문제라면 Jetson 한 보드 폴백으로 전환한다.
