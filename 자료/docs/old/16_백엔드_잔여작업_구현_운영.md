## 2. 기기 provisioning 운영 계약

내부 API는 Spring 프로세스가 `127.0.0.1:8081`에 바인딩된 상태에서만 사용한다. Nginx는 `/internal/**`을 외부에 프록시하지 않는다. 또한 다음 두 조건을 모두 검사한다.

1. 요청 출발지가 loopback 주소일 것
2. `X-Provisioning-Key`가 서버 환경변수 `DEVICE_PROVISIONING_ADMIN_KEY`와 일치할 것

`DEVICE_PROVISIONING_ENABLED`의 기본값은 `false`이며 운영에서만 명시적으로 활성화한다. 관리자 키는 32자 이상이어야 한다.

### 2.1 최초 기기 등록

```bash
curl --fail-with-body http://127.0.0.1:8081/internal/admin/devices \
  -H "X-Provisioning-Key: $DEVICE_PROVISIONING_ADMIN_KEY" \
  -H 'Content-Type: application/json' \
  -d '{"serialNumber":"WJ-2026-0001","name":"William James Camera","model":"WJ-01","firmwareVersion":"1.0.0"}'
```

응답의 `bearerToken` 평문은 이 응답에서만 확인할 수 있다. 서버 DB에는 토큰의 `keyId`와 secret SHA-256 해시만 저장한다. 평문 토큰은 기기의 보안 저장소에 즉시 주입하고 터미널 기록·메신저·문서에 남기지 않는다.

### 2.2 credential 교체·회수

```bash
curl --fail-with-body -X POST \
  -H "X-Provisioning-Key: $DEVICE_PROVISIONING_ADMIN_KEY" \
  http://127.0.0.1:8081/internal/admin/devices/{deviceId}/credentials/rotate

curl --fail-with-body -X DELETE \
  -H "X-Provisioning-Key: $DEVICE_PROVISIONING_ADMIN_KEY" \
  http://127.0.0.1:8081/internal/admin/devices/{deviceId}/credentials
```

교체는 기존 ACTIVE credential 회수와 신규 해시 저장을 한 DB 트랜잭션에서 수행한다. 미등록 기기는 이 credential로 등록 코드만 발급할 수 있으며 영상 업로드는 claim 완료 후에만 허용된다.

## 3. 사용자 API 추가 계약

### 3.1 캘린더 기간 조회

```http
GET /api/videos?deviceId={deviceId}&from=2026-07-01T00:00:00%2B09:00&to=2026-08-01T00:00:00%2B09:00
```

### 3.2 영상 통계

```http
GET /api/devices/{deviceId}/stats?from=2026-07-01&to=2026-07-31&timeZone=Asia%2FSeoul
```

조회 기간은 최대 366일이고 기본값은 요청 시간대 기준 최근 30일이다. 활성 멤버십이 없는 기기는 404로 숨긴다.

## 4. 로그인 rate limit

- 기준: 정규화 이메일 SHA-256, 접속 IP SHA-256 각각 실패 5회/10분
- 초과 응답: `429 LOGIN_RATE_LIMITED`
- 성공·실패 이력에는 이메일과 IP 원문을 저장하지 않는다.
- Nginx가 설정한 `X-Forwarded-For`를 loopback 바인딩된 Spring/Tomcat이 해석하도록 `server.forward-headers-strategy=native`를 적용한다.

## 5. 백업과 복구

`william-james-backup.timer`는 매일 03:30(Asia/Seoul)에 실행한다. 결과는 `/home/ubuntu/william-james/backups/data/<UTC timestamp>/`에 생성된다.

- `postgres.dump`: PostgreSQL custom-format dump
- `minio-data.tar.gz`: MinIO `/data` 압축본
- `SHA256SUMS`: 두 파일의 무결성 값

복구는 기존 데이터를 덮어쓸 수 있으므로 서비스 중지, 대상 확인, 별도 복구 DB/버킷에서 검증 후 수행한다. 월 1회 별도 환경에서 dump restore와 객체 압축 해제를 시험하고 결과를 운영 기록에 남긴다. 현재 백업은 같은 EC2 디스크에 있으므로 운영 전 off-instance 저장소 복제를 추가해야 한다.

## 6. 모니터링과 CI/CD

`william-james-monitor.timer`는 5분마다 다음을 검사하고 실패를 systemd journal에 기록한다.

- Spring Actuator health
- Nginx와 백엔드 systemd 상태
- PostgreSQL·MinIO·Mosquitto·MediaMTX 컨테이너 실행 상태
- 서비스 디스크 사용률 85% 미만

GitLab 파이프라인은 테스트 실패 시 패키징과 배포를 차단한다. production 배포는 기본 브랜치에서 수동 승인하며 다음 protected CI 변수가 필요하다.

- `DEPLOY_HOST`
- `DEPLOY_USER`
- `DEPLOY_SSH_PRIVATE_KEY`
