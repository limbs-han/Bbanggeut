> 문서 버전: 1.4 (클라이언트 편집·편집본 미저장·자동 인물 추적 방향 반영)
> 기준 문서: `윌리엄_제임스_프로젝트_기획서.md`  
> 개발 기간: 7월 20일 ~ 7월 31일  
> 범위 표기: `[기본]`은 MVP 필수 범위, `[심화]`는 MVP 완료 후 선택 구현 범위다.

## 1. 목적과 범위

윌리엄 제임스는 웃음소리, 호출어 또는 터치를 계기로 이미 지나간 순간을 자동으로 보존하는 IoT·온디바이스 AI 서비스다. 사용자는 Flutter **IoT 기기 관리 앱**에서 기기를 등록·관리하고, 권한이 있는 사용자만 저장된 영상을 조회·편집·다운로드할 수 있다.

**서비스 방향성 (팀 확정):**

1. 앱의 성격은 **IoT 기기 관리 앱**이며, 공개 영상 피드·영상 플랫폼 앱이 아니다.
2. **일반 편집은 앱에서 수행하고 편집 결과는 서버에 저장하지 않는다.** 사용자가 기기에 저장하거나 공유 대상으로 직접 내보낸다.
3. 저장된 영상은 **같은 기기의 구성원(가족)만** 조회할 수 있다. 구성원 관계는 사용자↔기기 다대다 `DeviceMembership`으로 관리한다.
4. 영상은 기기별 **보관 기간이 지나면 자동 삭제**한다. 이 보관 정책은 보관 연장 등 부가 서비스·수익 모델(BM)의 근거로 활용한다(구체안은 별도 설계 항목).
5. 앱은 저장 영상을 **갤러리·캘린더·통계** 관점으로 보여주는 대시보드를 제공한다.

이 문서는 앱, 백엔드, AI, IoT 및 저장소가 공동으로 만족해야 할 기능·비기능 요구사항과 인수 기준을 정의한다. 각 요구사항 ID는 구현, API, 테스트 및 결함 관리에서 변경하지 않는다.

## 2. 용어와 사용자

| 용어 | 정의 |
| --- | --- |
| `OWNER` | 특정 기기를 최초 등록한 소유자. 기기마다 활성 `OWNER`는 1명이며 해당 기기·구성원·영상 관리 권한을 가진다. |
| `MEMBER` | 특정 기기 `OWNER`의 초대를 수락한 사용자. 해당 기기 영상의 조회·다운로드 및 제한된 편집 권한을 가진다. |
| `DeviceMembership` | 사용자와 기기의 다대다 관계. `user_id`, `device_id`, 기기별 역할(`OWNER/MEMBER`)과 상태(`ACTIVE/REVOKED`)를 가진다. |
| 이벤트 시각 `T` | 웃음, 호출어 또는 터치가 확정된 시각 |
| 순환 버퍼 | 최근 영상을 짧은 세그먼트로 임시 보관하고 오래된 세그먼트를 자동 삭제하는 로컬 저장 영역 |
| 서명 URL | 권한 검사 후 짧은 시간 동안만 사용할 수 있는 업로드·재생·다운로드 주소 |
| 등록 모드 | 기기를 물리적으로 조작한 뒤 제한 시간 동안만 최초 등록을 허용하는 상태 |
| 등록 코드 | 등록 모드 진입 시 서버가 생성해 기기 화면(7" HDMI LCD)에 표시하는 1회용 코드. 혼동 문자를 제외한 대문자·숫자 32자 문자셋 8자리(`XXXX-XXXX` 표시), 120초 만료, 서버에는 해시만 저장한다. |

| `FR-B-018` | `[폐기]` 서버 편집본 영구 저장 | 일반 편집본 미저장 결정으로 폐기한다. 기존 배포 DB의 편집 작업 이력은 호환성 때문에 즉시 삭제하지 않지만 신규 작업과 `EDIT_OUTPUT` 객체는 생성하지 않는다. |
| `FR-B-020` | `[기본]` 카메라는 사람을 찾고 검출된 사람들의 중앙을 자동 추적해야 한다. | 사람이 없으면 안전한 팬 범위에서 스캔한다. 한 명 이상이 검출되면 모든 유효 사람 바운딩 박스 중심의 산술 평균을 목표점으로 삼고 카메라 중심과의 오차가 허용 범위를 넘을 때 팬·틸트를 이동한다. 이동 중 검출 인원이 추가·제거되면 매 추적 주기마다 목표점을 다시 계산한다. 일정 시간 검출이 없으면 `TRACKING`에서 `SCANNING`으로 복귀하며 모터 한계·최대 속도·비상 정지를 항상 우선한다. |

`FR-B-020`의 탐지·상태 전이·모터 제어는 IoT/AI 엣지 내부 책임이다. MVP 백엔드는 추적 상태나 좌표를 저장·조회·제어하지 않는다.
| `FR-B-012` | `[기본]` 사용자는 접근 권한이 있는 기기의 실시간 보기를 요청할 때만 HLS 스트림을 시작하고 종료할 수 있어야 한다. | 앱의 `POST` 스트림 세션 요청에서 서버가 대상 기기의 활성 `DeviceMembership(OWNER/MEMBER)`을 확인한다. 멤버십이 없으면 존재 은닉 `404`를 반환하고, 허용되면 세션을 `PENDING`으로 만들면서 `lastActivityAt=createdAt`, `viewerExpiresAt=createdAt+45초`로 초기화한다. 첫 시청자일 때 서버는 `{env}/wj/v1/devices/{deviceId}/commands` 단일 토픽으로 `START_STREAM`을 보내고, 활성 시청 중에는 `EXTEND_STREAM`으로 기본 120초 `hardExpiresAt`을 주기적으로 연장한다. 앱은 준비되는 수초 동안 대기 상태를 표시하고 `PENDING/READY` 화면을 유지하는 동안 15초마다 heartbeat를 보내며, 유효 heartbeat마다 `lastActivityAt`과 `viewerExpiresAt=lastActivityAt+45초`를 갱신한다. 정상 이탈은 `DELETE`로 `CLOSED`, `viewerExpiresAt` 도달은 `EXPIRED`, 시작 실패는 `FAILED`가 된다. `PENDING`에서 첫 heartbeat 전에 앱이 사라져도 `createdAt+45초`에 만료하고 마지막 시청자라면 `createdAt+60초`에 `STOP_STREAM`을 보낸다. 그 밖의 중지 기준은 마지막 유효 `lastActivityAt` 또는 정상 `DELETE` 시각부터 최대 60초이며, 45초 TTL 만료 뒤 60초를 다시 세지 않는다. 새 세션·heartbeat가 오면 예약된 중지를 취소한다. 여러 시청자는 기기당 하나의 송출을 공유한다. 엣지는 제어 경로가 끊겨도 마지막 `hardExpiresAt`에 자체 종료한다. 오프라인·준비 중·네트워크 끊김을 구분해 표시한다. |
| `FR-B-013` | `[기본]` 기기 화면에 표시된 1회용 등록 코드와 물리적 등록 모드를 함께 확인해 최초 사용자를 해당 기기의 유일한 `OWNER`로 등록해야 한다. | 등록 모드 진입 시 서버가 활성 코드 간 유일한 등록 코드를 CSPRNG로 생성해 기기 화면에 표시한다. 앱은 코드만 제출하고 서버는 코드 역조회로 대상 기기를 특정한다. 미등록(`UNCLAIMED`) 기기에서 코드가 유효(120초 이내·미사용)할 때만 활성 `DeviceMembership(OWNER)`이 한 건 생성되고, 만료·재사용·잘못된 코드와 이미 등록된 기기는 거부된다. 등록 시도 실패는 계정·IP당 5회/10분으로 제한한다. |
| `FR-B-014` | `[기본]` 특정 기기의 `OWNER`는 만료되는 1회용 초대로 해당 기기의 `MEMBER`를 추가할 수 있어야 한다. | 초대에는 대상 `device_id`와 수신자가 고정된다. 유효한 초대를 로그인한 수신자가 한 번만 수락할 수 있고, 만료·재사용·다른 수신자 사용은 거부된다. 수락 후 해당 기기의 활성 `DeviceMembership(MEMBER)`이 조회된다. |
| `FR-B-015` | `[기본]` 서버는 기기별 `OWNER`와 `MEMBER` 역할에 따라 모든 보호 기능을 인가해야 한다. | 사용자는 여러 기기에 서로 다른 역할로 참여할 수 있다. `MEMBER`는 해당 기기의 구성원 관리·기기 해제·보관 정책 변경을 할 수 없고, 그 기기의 `OWNER`만 수행한다. 같은 기기의 활성 `MEMBER`가 `OWNER` 전용 API를 직접 호출하면 `403`으로 차단된다. |
| `FR-B-016` | `[기본]` 특정 기기의 `OWNER`는 그 기기의 구성원 권한을 즉시 회수할 수 있어야 한다. | 회수된 사용자는 다음 보호 API 요청부터 해당 기기의 영상·스트림·다운로드 URL을 새로 발급받지 못하며 리소스 존재를 숨기는 `404`를 받는다. 해당 사용자의 활성 라이브 세션은 즉시 `EXPIRED` 처리하고 이후 playlist·segment 요청을 거부한다. 다른 기기의 활성 멤버십과 다른 사용자의 시청 세션은 변경되지 않는다. |
| `FR-B-017` | `[기본]` 영상은 생성한 기기 단위로 분리하고 모든 요청에서 `video.device_id`에 대한 활성 멤버십과 역할을 검증해야 한다. | 해당 기기의 활성 멤버십이 없는 사용자가 영상 ID를 추측해 목록·상세·재생·편집·다운로드·삭제를 호출해도 데이터가 노출되지 않고 `404`를 반환한다. 같은 기기의 활성 구성원이지만 요청 작업에 필요한 역할이 부족한 경우에만 `403`을 반환한다. |
| `FR-B-019` | `[기본]` 해당 기기의 `OWNER`는 기기를 해제(양도 준비)할 수 있어야 하며, 해제된 기기는 새 기기처럼만 재등록되어야 한다. | 해제 전 앱은 영상 전체 삭제를 경고하고 다운로드를 안내한다. 해제 트랜잭션에서 기존 device 행은 `REVOKED`로 종결되고 그 기기의 영상·멤버십·자격 증명이 삭제(또는 삭제 작업 등록)되며, 같은 시리얼의 새 `UNCLAIMED` device 행이 생성된다. 새 소유자는 일반 등록 절차(FR-B-013)로만 `OWNER`가 되고, 이전 영상에는 어떤 사용자도 접근할 수 없다. 인쇄식 제품 코드와 물리 리셋에 의한 소유권 이전 경로는 제공하지 않는다. |

### 4.1 기본 비기능 요구사항

| ID | 분류 | 요구사항 및 측정 기준 |
| --- | --- | --- |
| `NFR-B-001` | 보안·전송 | 앱↔서버, 기기↔서버 및 기기↔저장소의 운영 통신은 TLS를 사용한다. 평문 HTTP로 보호 API 또는 영상 업로드를 시도하면 거부하거나 HTTPS로 강제 전환한다. |
| `NFR-B-002` | 보안·자격 증명 | 비밀번호는 BCrypt 또는 Argon2로 단방향 해시하고, 접근 토큰·갱신 토큰·기기 자격 증명을 분리한다. 로그와 Git 저장소에 평문 비밀번호, 토큰, 등록 코드를 남기지 않는다. 인증 실패에는 시도 제한을 적용한다. |
| `NFR-B-003` | 보안·저장소·라이브 자격 | 객체 저장소는 비공개로 유지한다. 저장 영상의 MinIO/S3 재생·다운로드 서명 URL은 발급 후 권한이 회수돼도 1~5분 만료 전까지 남을 수 있으므로 만료를 짧게 한다. 라이브에는 이 저장 영상 서명 URL을 재사용하지 않는다. 라이브의 이후 모든 playlist·segment 요청은 세션 소유자, 세션 `READY` 상태, `viewerExpiresAt`, 대상 기기의 활성 `DeviceMembership`을 검증해야 하며 `CLOSED/EXPIRED` 또는 권한 회수 직후부터 거부해야 한다. 구현은 ① 인증 프록시가 매 playlist·segment 요청을 검사하거나 ② 매우 짧은 opaque 토큰을 미디어 계층이 요청마다 introspection하는 후보 중 선택하며 아직 미확정이다. 단순히 수명이 짧은 자체 검증 JWT만 사용하는 방식은 즉시 차단 기준을 충족하지 않는다. 객체 키와 스트림 경로는 추측 가능한 순번만으로 만들지 않는다. |
| `NFR-B-004` | 보안·인가 | 모든 영상·스트림·구성원·기기 API는 서버에서 인증 사용자와 대상 기기의 활성 `DeviceMembership` 및 역할을 검증한다. 영상 권한은 반드시 서버가 조회한 `video.device_id`로 판정하며, 임의 ID 변경·다른 계정 토큰·클라이언트 역할 값 변조로 우회할 수 없어야 한다. 라이브 인증 계층 후보도 playlist·segment마다 토큰의 세션 소유자와 현재 멤버십을 서버 상태로 재검증해야 한다. |
| `NFR-B-005` | 개인정보 | 단일 프라이버시 LED 기준으로 카메라 프레임 읽기·순환 녹화 중에는 상시 점등하고, 원격 라이브 송출 중에는 눈에 띄는 1Hz 점멸(500ms ON/500ms OFF)로 구분한다. 2색 LED를 쓰면 녹화 색상은 계속 점등하고 별도 라이브 색상을 1Hz 점멸하는 대안을 허용한다. 촬영 중 LED를 지속 소등하는 사용자 옵션이나 오류 상태를 허용하지 않으며, 카메라·송출 상태와 패턴을 실기기에서 검증한다. 영구 저장 대상으로 확정되지 않은 로컬 세그먼트는 보관 시간 이후 자동 삭제하고, 라이브는 활성 세션 동안만 전달하며 이벤트 저장소에 보관하지 않는다. |
| `NFR-B-006` | 신뢰성·네트워크 | 업로드 실패 시 지수 또는 고정 백오프로 최소 3회 재시도하며, 재부팅 또는 네트워크 복구 후 미완료 업로드를 다시 처리한다. 동일 이벤트의 중복 요청은 멱등하게 처리한다. |
| `NFR-B-007` | 성능 | 정상 부하의 API 목록·상세 요청은 테스트 환경에서 95백분위 2초 이내, 대시보드는 3초 이내 응답한다. 로컬 편집 성능은 기준 Android 실기기에서 별도로 측정한다. |
| `NFR-B-008` | 영상 정확성·인코딩 | 이벤트 영상과 앱 로컬 편집 결과의 요청 시작·종료 대비 오차는 최대 `±2초` 또는 세그먼트 1개 길이 중 큰 값 이내여야 한다. Jetson의 단일 H.264/AAC 인코더 출력을 순환 버퍼와 기기 live publisher에 tee하고, 별도 미디어 계층 후보가 이를 재인코딩 없이 HLS로 remux·fan-out(`-c copy`)하는 것을 기본으로 한다. GOP/keyframe 간격은 2초를 기준으로 HLS 세그먼트 경계와 정렬하며, 실제 장비 검증으로 확정한다. |
| `NFR-B-009` | 감사 가능성 | 로그인 실패, 기기 등록, 초대 수락·회수, 영상 조회·재생 URL 발급·다운로드·삭제, 라이브 세션 생성·만료·종료와 MQTT `START_STREAM/EXTEND_STREAM/STOP_STREAM` 결과를 사용자/기기 ID, 대상, 시각, 결과와 함께 기록한다. 기기 밖에서 수행되는 로컬 편집 내용은 서버 감사 로그 대상이 아니다. HLS 경로·재생 토큰은 기록하지 않으며 일반 사용자는 감사 로그를 변조할 수 없다. |
| `NFR-B-010` | 호환성·사용성 | MVP 앱은 팀이 확정한 기준 Android 실기기와 최소 2개 화면 크기에서 핵심 시나리오를 완료해야 한다. 로딩, 빈 상태, 권한 없음, 오프라인 오류를 구분하여 표시한다. |
| `NFR-B-011` | 장시간 안정성 | IoT 프로그램은 30분 이상 순환 녹화 중 비정상 종료 없이 동작하고, 버퍼 파일 수와 사용량이 설정 상한 안에서 안정화되어야 한다. 라이브 세션은 생성 시 `lastActivityAt=createdAt`, `viewerExpiresAt=createdAt+45초`로 초기화하고 이후 유효 heartbeat마다 두 값을 갱신한다. 첫 heartbeat가 없는 `PENDING` 세션은 `createdAt+45초`에 회수하며 마지막 시청자라면 `createdAt+60초`에 `STOP_STREAM`을 보내야 한다. 그 밖에는 마지막 유효 `lastActivityAt` 또는 정상 `DELETE`와 같은 기준시각부터 최대 60초의 idle stop을 사용하고 TTL 만료 뒤 60초를 다시 세지 않으며, 새 세션 시 중지를 취소한다. `START_STREAM/EXTEND_STREAM`의 `hardExpiresAt` 기본 간격은 120초이며 활성 시청 중에만 연장한다. 서버 또는 MQTT 제어 경로가 끊기면 엣지는 마지막 `hardExpiresAt`, 즉 마지막 유효 연장으로부터 약 120초 안에 자체 종료해야 한다. HLS 연결이 일시 중단되면 재연결 또는 명시적 재시도 UI를 제공한다. |
| `NFR-B-012` | 삭제·보관 | 사용자가 영상을 삭제하면 앱/API 조회와 새 URL 발급은 즉시 차단되고, 객체와 관련 파생물은 10분 이내 삭제되거나 삭제 작업 상태로 추적되어야 한다. 실패한 삭제 작업은 재시도 가능해야 한다. |

| 라이브 미디어 계층 | `[기본·미확정]` | 기기 live publisher가 전달한 단일 H.264/AAC ingest를 `-c copy`로 HLS remux·fan-out하는 전용 미디어 서버 또는 동등 구성을 후보로 비교한다. MediaMTX 등 채택 제품은 부하·인증·HLS 호환성 검증 후 확정하며 현재 확정 기술로 간주하지 않는다. |
| 푸시 | `[심화]` | Firebase Cloud Messaging 후보를 사용하되 실제 채택 여부와 자격 증명 관리 방식을 기록한다. |

## 6. 범위 제외 및 가정

- `[기본]` 이 서비스는 IoT 기기 관리 앱이다. 불특정 다수에게 영상을 공개·추천하는 영상 플랫폼 기능(공개 피드, 팔로우, 외부 공유형 게시)은 제공하지 않는다.
- `[기본]` iOS 배포, 공개 영상 피드, 결제, 소셜 로그인, 완전한 종단간 암호화는 MVP 범위에서 제외한다.
- `[기본]` 영상은 기기별 보관 기간 만료 시 자동 삭제하는 것을 필수로 하며, 보관 연장·영구 보관·2차 콘텐츠 생성 등 보관 정책을 활용한 부가 서비스·수익 모델(BM)은 확정 후 별도 요구사항으로 추가한다.
- `[기본]` YAMNet은 웃음 분류에 사용하며 “헤이 제임스” 호출어는 별도 Keyword Spotting 방식이 필요하다. 호출어 통합이 지연되어도 터치 입력은 필수 폴백으로 유지한다.
- `[기본]` 영상 파일은 백엔드 애플리케이션을 경유하지 않고 기기가 객체 저장소에 직접 업로드한다.
- `[기본]` 일반 편집본은 앱 샌드박스 또는 사용자가 선택한 기기 저장소/공유 대상으로만 내보내며 서버 API·DB·MinIO에 업로드하지 않는다.
- `[기본]` 이벤트 MP4의 MinIO/S3 직접 업로드 경로와 `Jetson 단일 인코더 출력 → 기기 live publisher → 별도 미디어 계층 후보의 HLS -c copy remux·fan-out` 경로는 분리한다. 라이브 HLS를 이벤트 영상 객체로 저장하는 구조는 사용하지 않는다.
- `[기본]` 최초 라이브 재생에는 기기 송출 시작과 첫 HLS 세그먼트 준비에 수초가 걸릴 수 있으며, 앱은 이를 오류가 아닌 `PENDING`으로 표시한다.
- `[심화]` AI 편집·새 영상·만화 등 생성형 결과물의 구체 기능, 처리 위치, 모델, 입력/출력 보관 정책은 미확정이다. 별도 제품 결정과 개인정보 검토 전에는 API·DB 스키마를 추가하거나 기능을 활성화하지 않는다.
- `[심화·선택]` 이동형 카메라는 고정형 추억 카메라 MVP와 독립된 실험 범위다.
