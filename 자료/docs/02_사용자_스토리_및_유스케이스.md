## 1. 액터

| 액터 | 설명 |
| --- | --- |
| 비회원 | 회원가입 또는 로그인을 시작하는 사용자 |
| `OWNER` | 특정 기기를 최초 등록하고 그 기기의 구성원·설정·영상을 관리하는 사용자. 기기마다 1명 |
| `MEMBER` | 특정 기기 `OWNER`의 초대를 수락해 그 기기에 허용된 영상 기능을 사용하는 사용자 |
| IoT 기기 | 카메라·마이크·터치·LED를 제어하고 영상을 순환 녹화·업로드하는 Jetson/Raspberry Pi 시스템 |
| AI 감지 모듈 | YAMNet, YOLO, 호출어 모델 및 선택적 MediaPipe로 이벤트를 판정하는 온디바이스 모듈 |
| 백엔드 | 인증·인가, 메타데이터, 스트림 세션·시청자 상태, 작업 상태, 서명 URL 및 감사 로그를 관리하는 Spring Boot 서버 |
| 객체 저장소 | 비공개 영상 객체를 저장하고 제한된 서명 URL 요청만 허용하는 MinIO/S3 |
| 라이브 미디어 계층 | Jetson의 기기 live publisher가 보낸 단일 ingest를 받아 `-c copy` 또는 동등한 무재인코딩 방식으로 HLS remux·다중 시청 fan-out하는 별도 구성요소. MediaMTX 등은 구현 후보이며 제품은 미확정 |
| 스케줄러 | 보관 기한과 삭제·재시도 작업을 실행하는 서버 또는 기기 작업자 |

## 3. 기본 유스케이스

### `UC-B-001` 계정 인증

| 항목 | 내용 |
| --- | --- |
| 범위 | `[기본]` |
| 주 액터 | 비회원, `OWNER`, `MEMBER` |
| 선행 조건 | 앱이 백엔드에 TLS로 연결된다. |
| 트리거 | 회원가입, 로그인, 토큰 재발급 또는 로그아웃을 선택한다. |
| 기본 흐름 | 1) 사용자가 계정 정보를 입력한다. 2) 서버가 입력 형식과 자격 증명을 검증한다. 3) 성공 시 접근·갱신 토큰을 분리 발급한다. 4) 앱은 민감 토큰을 안전 저장소에 보관한다. 5) 보호 API 호출 시 서버가 토큰과 사용자 상태를 검증한다. |
| 대안·오류 | 중복 계정은 `409`, 잘못된 자격 증명·만료 토큰은 `401`, 반복 실패는 시도 제한 응답을 제공한다. 로그아웃된 갱신 토큰은 재사용할 수 없다. |
| 종료 조건 | 성공 시 인증 세션이 형성되며 실패 시 보호 데이터는 노출되지 않는다. |
| 인수 기준 | `FR-B-001`, `NFR-B-001`, `NFR-B-002`를 만족한다. |

### `UC-B-002` 최초 기기 등록

| 항목 | 내용 |
| --- | --- |
| 범위 | `[기본]` |
| 주 액터 | 로그인 사용자, IoT 기기, 백엔드 |
| 선행 조건 | 기기는 미등록(`UNCLAIMED`) 상태이며 서버와 통신할 수 있다. |
| 트리거 | 사용자가 기기의 물리 버튼/터치를 길게 눌러 등록 모드를 활성화한다. |
| 기본 흐름 | 1) 기기가 제한 시간의 등록 모드임을 서버에 알리고 1회용 등록 코드를 발급받아 7" LCD에 표시한다. 2) 사용자가 앱에서 화면의 코드를 입력한다. 3) 서버가 코드 해시 역조회로 기기를 특정하고 코드 유효성(120초·미사용), 기존 `OWNER` 부재, 시도 횟수를 검증한다. 4) 사용자와 기기를 잇는 활성 `DeviceMembership(OWNER)`을 한 건 생성한다. 5) 등록 코드를 사용 처리하고 고유 기기 자격 증명을 발급한다. |
| 대안·오류 | 등록 모드 미활성, 만료, 잘못된 코드, 이미 등록된 기기, 재사용 코드는 거부한다. 실패는 계정·IP당 5회/10분으로 제한한다. 네트워크 실패 시 등록 성공 여부를 재조회해 중복 소유권 생성을 막는다. |
| 종료 조건 | 성공 시 사용자와 기기가 `OWNER` 멤버십으로 연결되고, 기기당 활성 `OWNER`는 한 명이며 사용된 코드는 재사용할 수 없다. |
| 인수 기준 | 두 인증 요소를 모두 만족한 경우에만 `FR-B-013`이 성립한다. |

### `UC-B-003` 구성원 초대 및 권한 회수

| 항목 | 내용 |
| --- | --- |
| 범위 | `[기본]` |
| 주 액터 | `OWNER`, 초대받은 사용자, 백엔드 |
| 선행 조건 | `OWNER`가 대상 기기의 활성 `DeviceMembership(OWNER)`을 보유한다. |
| 트리거 | `OWNER`가 대상 기기의 구성원 초대를 생성하거나 기존 `MEMBER`의 권한 회수를 선택한다. |
| 기본 흐름 | 1) `OWNER`가 대상 기기, 수신자와 초대 만료 시간을 지정한다. 2) 서버가 기기와 수신자에 묶인 1회용 토큰을 만든다. 3) 수신자가 자신의 계정으로 로그인해 수락한다. 4) 서버가 대상 기기·수신자·만료·미사용 여부를 검증하고 활성 `DeviceMembership(MEMBER)`을 만든다. 5) `OWNER`가 회수하면 그 기기의 관계만 비활성화하고 후속 접근을 차단한다. |
| 대안·오류 | 해당 기기 `MEMBER`의 초대·회수 시도, 만료/재사용 토큰, 다른 수신자의 수락, 다른 기기용 초대 사용, `OWNER` 멤버십 제거는 거부한다. |
| 종료 조건 | 구성원 목록과 실제 API 권한이 즉시 일치한다. |
| 인수 기준 | `FR-B-014~016`을 만족하고 회수된 사용자의 다음 보호 요청이 차단된다. |

### `UC-B-004` 웃음 자동 녹화

| 항목 | 내용 |
| --- | --- |
| 범위 | `[기본]` |
| 주 액터 | AI 감지 모듈, IoT 기기 |
| 선행 조건 | 카메라·마이크와 순환 버퍼가 정상 동작하며 저장 공간이 상한 미만이다. |
| 트리거 | YAMNet 파이프라인이 웃음 이벤트 시각 `T`를 확정한다. |
| 기본 흐름 | 1) 기기가 `T-60초`부터의 기존 세그먼트를 잠근다. 2) `T+60초`까지 추가 녹화한다. 3) 병합 창 내 후속 웃음은 같은 이벤트에 연결한다. 4) 필요한 세그먼트를 FFmpeg로 병합한다. 5) 감지 유형·시각·이벤트 ID와 업로드 큐에 넣는다. |
| 대안·오류 | 버퍼 부족 시 가용 구간과 실패/축약 사유를 기록한다. 병합 창 밖 이벤트는 별도 영상으로 만든다. FFmpeg 실패 시 원본 세그먼트를 보존하고 재처리한다. |
| 종료 조건 | 중복 없는 `LAUGHTER` 영상 또는 추적 가능한 실패 상태가 생성된다. |
| 인수 기준 | `FR-B-002`, `FR-B-003`, `FR-B-005`, `NFR-B-008`을 만족한다. |

### `UC-B-005` 호출어·터치 녹화

| 항목 | 내용 |
| --- | --- |

| 종료 조건 | 직전 약 120초 영상 1건 또는 추적 가능한 실패 상태가 생성된다. |

### `UC-B-006` 영상 업로드 및 네트워크 복구

| 항목 | 내용 |
| --- | --- |
| 범위 | `[기본]` |
| 주 액터 | IoT 기기, 백엔드, 객체 저장소 |
| 선행 조건 | 기기에 유효한 자격 증명과 로컬 영상·이벤트 ID가 있다. |
| 트리거 | 영상이 업로드 큐에 들어간다. |
| 기본 흐름 | 1) 기기가 사용자 JWT와 분리된 기기 자격 증명으로 인증한 뒤 업로드 URL을 요청한다. 2) 서버는 인증된 `device_id`로 `private/{deviceId}/...` 범위의 객체 키를 생성한다. 3) 기기가 저장소에 직접 업로드한다. 4) 해시·크기·이벤트 ID와 완료를 통지한다. 5) 서버가 객체를 확인하고 같은 `device_id`의 영상 메타데이터 상태를 완료로 전환한다. |
| 대안·오류 | 인터넷·저장소·서버 실패 시 최소 3회 백오프 재시도하고 큐를 보존한다. 재부팅 후 큐를 복구한다. 만료 URL은 새로 발급받는다. 동일 완료 통지는 멱등 처리한다. 폐기된 기기 자격 증명은 거부한다. |
| 종료 조건 | 영상 객체와 메타데이터가 정확히 1건 연결되거나 재시도 가능한 실패 상태로 남는다. |
| 인수 기준 | `FR-B-006`, `NFR-B-003`, `NFR-B-006`, `NFR-B-011`을 만족한다. |

### `UC-B-009` 대시보드 및 실시간 스트리밍

| 항목 | 내용 |
| --- | --- |

| 트리거 | 사용자가 홈을 열거나 특정 기기의 ‘실시간 보기’를 선택한다. |
| 기본 흐름 | 1) 서버가 사용자의 활성 기기 멤버십 범위에서 기기·영상 집계를 반환한다. 2) 앱이 온라인 상태와 최근 영상을 표시한다. 3) 앱이 `POST /api/devices/{deviceId}/stream-sessions`를 요청한다. 4) 서버가 대상 기기의 활성 `DeviceMembership(OWNER/MEMBER)`을 검증하고 시청 세션을 `PENDING`으로 만든다. 생성 시 `lastActivityAt=createdAt`, `viewerExpiresAt=createdAt+45초`, 초기 `stopDeadline=createdAt+60초`로 잡아 첫 heartbeat가 없어도 회수한다. 5) 해당 기기의 첫 활성 시청자라면 단일 MQTT 명령 토픽 `{env}/wj/v1/devices/{deviceId}/commands`에 `START_STREAM`을 발행하고, 이미 송출 중이면 기존 기기 송출을 공유한다. 6) Jetson의 단일 H.264/AAC 인코더 출력을 순환 녹화와 기기 live publisher로 tee한다. publisher는 이벤트 MinIO/S3 경로와 분리된 ingest 하나를 별도 미디어 계층 후보에 보내고, 이 계층이 `-c copy` 또는 동등한 방식으로 HLS remux·시청자 fan-out을 수행한다. 7) 첫 세그먼트가 준비되는 수초 동안 앱은 `PENDING`을 표시하고 준비 후 `READY`로 재생하며, 라이브 화면이 `PENDING/READY`인 동안 15초마다 heartbeat한다. 8) HLS playlist·segment 자격은 해당 StreamSession 소유자와 대상 기기의 `ACTIVE DeviceMembership`에 종속된다. 미디어 계층은 요청마다 백엔드에 검증하거나 매우 짧은 불투명 introspection token으로 같은 조건을 확인한다. 9) heartbeat가 성공할 때마다 `lastActivityAt`, `viewerExpiresAt=lastActivityAt+45초`, `stopDeadline=lastActivityAt+60초`를 갱신한다. 활성 시청자가 있으면 서버는 같은 명령 토픽에 `EXTEND_STREAM`을 발행해 `hardExpiresAt`을 약 120초 뒤로 연장한다. 10) 정상 이탈 시 앱이 세션 `DELETE`를 호출해 `CLOSED`가 된다. 11) 마지막 시청자의 마지막 유효 활동부터 총 60초에 `STOP_STREAM`을 발행하며 새 세션·heartbeat가 오면 예약을 취소한다. |
| 대안·오류 | StreamSession 상태는 `PENDING`, `READY`, `CLOSED`, `EXPIRED`, `FAILED`만 사용한다. 첫 heartbeat가 없는 `PENDING`도 `createdAt+45초`에 `EXPIRED`가 되고 `createdAt+60초`가 초기 stop deadline이다. 기기 오프라인·시작 실패는 `FAILED`, 정상 DELETE는 `CLOSED`다. 앱은 `CLOSED/EXPIRED`를 하나의 종료 화면으로 매핑할 수 있다. playlist·segment 요청은 세션 소유자 불일치, `CLOSED/EXPIRED`, 권한 회수 시 즉시 차단한다. 이미 단말에 전달된 바이트는 회수할 수 없음을 개인정보 한계로 고지한다. 라이브 자격은 저장 영상의 1~5분 S3 서명 URL과 별개이며 HLS 주소를 재사용 가능한 저장 URL로 취급하지 않는다. `EXTEND_STREAM` 또는 `STOP_STREAM` 유실 시 기기는 마지막 연장부터 최대 약 120초인 `hardExpiresAt`에 자체 종료한다. |
| 종료 조건 | 사용자는 현재 상태를 오해하지 않고 대시보드 또는 스트림을 확인하며, 시청자가 없는 기기는 제한 시간 안에 송출을 중단한다. |
| 인수 기준 | `FR-B-011`, `FR-B-012`, `NFR-B-007`, `NFR-B-010~011`을 만족한다. |

## 5. 핵심 종단간 시나리오

### `E2E-B-001` 최초 소유자부터 웃음 영상 재생까지

1. 사용자가 가입·로그인한다(`UC-B-001`).
2. 실물 기기를 등록 모드로 전환하고 최초 등록한다(`UC-B-002`).
3. 기기가 2분 이상 순환 녹화한다.
4. 웃음 이벤트가 발생해 전후 영상이 생성된다(`UC-B-004`).
5. 네트워크가 정상 또는 복구된 뒤 영상이 한 번만 업로드된다(`UC-B-006`).
6. 앱 대시보드와 목록에 영상이 나타난다(`UC-B-007`, `UC-B-009`).
7. 사용자가 재생, 구간 편집 및 다운로드한다(`UC-B-007`, `UC-B-008`).

완료 기준: 각 단계의 요구사항과 연결된 기본 테스트가 모두 수행되어야 하며, 결과가 기록되기 전에는 성공으로 간주하지 않는다.

### `E2E-B-002` 기기별 구성원 초대와 권한 회수

1. 기기 A의 `OWNER`가 로그인한 수신자에게 기기 A에 묶인 만료형 1회 초대를 보낸다.
2. 수신자가 초대를 수락해 기기 A의 `MEMBER`가 된다.
3. `MEMBER`가 기기 A의 허용된 영상을 조회·다운로드한다.
4. `MEMBER`가 구성원 관리 또는 멤버십이 없는 기기 B의 영상 접근을 시도하면 거부된다.
5. `OWNER`가 기기 A의 권한을 회수한다.
6. 회수된 사용자의 기기 A 목록·재생·다운로드 URL 요청은 차단되고, 별도로 보유한 다른 기기의 활성 멤버십은 유지된다.

완료 기준: `UC-B-003`, `UC-B-007`, `UC-B-010`의 정상·오류 흐름이 모두 검증되어야 한다.

### `E2E-B-003` 다중 시청자 온디맨드 라이브

1. 기기 A의 `OWNER`가 라이브 세션을 생성하면 권한 검사 후 `PENDING`이 반환되고 `{env}/wj/v1/devices/{deviceId}/commands`에 `START_STREAM`이 한 번 전송된다.
2. 기기 A의 `MEMBER`가 추가 세션을 생성하면 별도 기기 송출을 만들지 않고 기존 송출을 공유한다.
3. 세션 생성 시 `lastActivityAt=createdAt`, `viewerExpiresAt=createdAt+45초`, 초기 stop deadline=`createdAt+60초`인지 확인한다. heartbeat 없이 `PENDING`에 머문 별도 세션은 각각 그 시각에 `EXPIRED`·STOP 처리된다.
4. 별도 미디어 계층 후보가 첫 HLS 세그먼트를 만들면 세션은 `READY`가 된다. 두 앱은 15초마다 각자 heartbeat를 전송하고, 서버는 활성 시청 중 같은 명령 토픽의 `EXTEND_STREAM`으로 `hardExpiresAt`을 약 120초 뒤로 갱신한다.
5. 각 playlist·segment 요청이 세션 소유자와 `ACTIVE DeviceMembership`을 재검증하는지 확인한다. 다른 계정, `CLOSED/EXPIRED` 세션, 권한 회수 후의 새 요청은 즉시 차단한다.
6. 첫 사용자가 세션을 `DELETE`하면 그 세션은 `CLOSED`가 되지만 두 번째 사용자가 활성 상태이므로 송출은 유지된다.
7. 마지막 세션의 정상 `DELETE` 또는 마지막 유효 heartbeat 시각을 기준으로 총 60초에 같은 명령 토픽으로 `STOP_STREAM`이 전송된다. heartbeat 세션은 마지막 heartbeat+45초에 `EXPIRED`가 되지만 그때부터 60초를 다시 세지 않으며, 새 세션이 오면 stop 예약을 취소한다.
8. 서버의 `EXTEND_STREAM`·`STOP_STREAM`이 기기에 전달되지 않아도 마지막 연장부터 최대 약 120초인 `hardExpiresAt`에 엣지 송출이 자체 종료된다.
9. Jetson의 단일 H.264/AAC 인코더가 순환 녹화와 기기 live publisher에 출력을 tee하고, 별도 미디어 계층 후보가 `-c copy` HLS remux·다중 시청 fan-out하는지 로그·프로세스 인자로 확인한다.
10. 라이브 HLS가 MinIO/S3 저장 영상 서명 URL과 분리되어 있고, 이미 수신한 바이트만 회수할 수 없는 잔여 한계를 기록한다.
11. 상태 API가 `PENDING/READY/CLOSED/EXPIRED/FAILED`만 반환하고 앱이 `CLOSED/EXPIRED`를 동일한 종료 화면에 매핑하는지 확인한다.

완료 기준: `FR-B-012`, `NFR-B-004`, `NFR-B-008`, `NFR-B-011`의 재생 권한·세션 수명주기·다중 시청·인코더 공유 조건을 모두 검증하고 측정 결과를 기록한다.
