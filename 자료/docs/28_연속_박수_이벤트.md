# 연속 박수와 웃음·박수 혼합 이벤트

## 목적

홈캠은 웃음뿐 아니라 연속 박수도 의미 있는 순간으로 감지한다. 단발 충격음은
이벤트로 취급하지 않으며, 웃음과 박수가 거의 동시에 발생하면 중복 영상을
만들지 않고 하나의 순간으로 보존한다.

## 판정 규칙

- YAMNet에서 `Clapping` 또는 `Applause` 점수가 임계값 이상이어야 한다.
- 1.44초 분석 구간에서 서로 분리된 충격음 onset이 3개 이상이어야 한다.
- 박수 양성 구간이 2회 연속되고 최소 0.4초 유지되어야 한다.
- 코드의 교차 유형 병합 기본값은 5초다.
- Jetson 운영 검증에서는 감지 지연을 반영해 교차 유형 병합 범위를 12초로
  설정했다.
- 같은 유형의 반복 감지는 기존 30초 병합 정책을 유지한다.
- 호출명 이벤트는 웃음·박수와 교차 병합하지 않는다.

## 혼합 이벤트 결과

웃음과 박수가 병합되면 영상은 한 번만 생성하고 서버에도 한 번만 업로드한다.
업로드 요청의 `eventTypes`, 로컬 업로드 상태, 영수증에는 `LAUGHTER`, `CLAP`
두 유형을 함께 기록한다.
대표 제목은 `웃음과 박수가 함께 포착됐어요`를 사용한다.

기존 클라이언트와의 호환을 위한 대표 유형은 `LAUGHTER`를 사용한다. 저장소의
박수 감지 기본값은 안전한 단계적 적용을 위해 꺼져 있다. 다중 유형 API와 앱이
반영된 Jetson 검증 장치에서는 박수 감지를 활성화해 종단 검증을 완료했다.

운영 검증값은 다음과 같다. 이 값은 저장소 기본값을 변경하지 않고 장치 환경
설정으로 적용한다.

```bash
YAMNET_CLAP_ENABLED=true
YAMNET_CLAP_THRESHOLD=0.30
YAMNET_CLAP_CONSECUTIVE=2
YAMNET_CLAP_REQUIRED_ONSETS=3
YAMNET_CLAP_MIN_ACTIVE_SECONDS=0.4
YAMNET_CLAP_MAX_GAP_SECONDS=0.75
YAMNET_CLAP_COOLDOWN=12
EVENT_CROSS_TYPE_MERGE_GAP_SECONDS=12
```

## 평가 데이터 확장

웃으면서 박수치는 10초 샘플을 validation과 test에 각각 5개 추가한다.
샘플 조건은 `laughter-with-clap`이고 라벨은 `laughter`와
`consecutive-clap`을 함께 사용한다.

혼합 샘플은 기존 깨끗한 웃음, 박수 단독, 말소리, 음악, 생활 소음 샘플을
대체하지 않는다. 이를 통해 혼합 소리에서 웃음 감지가 유지되는지와 박수 감지가
동시에 동작하는지를 별도로 확인한다.

## 검증 상태

- Device Python 테스트와 Shell 문법 검사를 통과해야 한다.
- 단발 박수와 2회 박수가 이벤트를 만들지 않는지 확인해야 한다.
- 3회 이상 연속 박수가 하나의 이벤트를 만드는지 확인해야 한다.
- 웃음과 박수가 운영 병합 범위 안에 발생할 때 영상이 한 개만 업로드되는지
  확인해야 한다.
- 백엔드와 앱의 다중 유형 계약 반영 후 영상·음성·두 이벤트 유형이 모두
  확인되어야 한다.

2026년 8월 3일 Jetson 실장 환경에서 단발 박수 무시, 연속 박수 감지, 12초
쿨다운, 서버 업로드, 앱 표시, 웃음·박수 혼합 영상 병합을 확인했다. 혼합 이벤트는
웃음이 먼저 감지된 뒤 즉시 박수치는 순서에서 두 트리거 간 4.253초로 병합됐다.
동시에 웃고 박수치거나 박수를 먼저 치는 경우에는 모델별 감지 지연과 음향 마스킹
때문에 같은 결과가 보장되지 않는다.
