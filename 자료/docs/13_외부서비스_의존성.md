# 외부 서비스 및 의존성 목록

## 1. 기본 원칙

- 핵심 영상과 음향 분석은 가능한 한 Jetson에서 수행한다.
- 외부 AI API로 사생활 영상을 보내지 않는 구성을 기본값으로 한다.
- 비용·약관·보관 정책이 확정되지 않은 외부 서비스는 MVP 의존성으로 추가하지 않는다.
- 모든 비밀값은 환경 변수 또는 비밀 관리 기능으로 주입하며 Git에 저장하지 않는다.

### 3.1 라이브 세션 상태 저장 원칙

- 앱은 활성 시청 세션에 15초마다 heartbeat하고 정상 이탈 시 DELETE를 호출한다. active TTL은 45초다.
- 생성 직후 PENDING은 `lastActivityAt=createdAt`, `viewerExpiresAt=createdAt+45초`, 초기 stop deadline=`createdAt+60초`다. 첫 heartbeat가 없어도 각각 EXPIRED·STOP 처리한다.
- 서버는 마지막 유효 heartbeat 또는 정상 DELETE를 기준으로 무시청 약 60초를 넘기지 않게 `STOP_STREAM` 시각을 계산한다. heartbeat가 45초에 만료된 뒤 60초를 다시 더하지 않으며, stop 전 새 세션이 오면 예약을 취소한다. `hardExpiresAt` 기본 lease는 120초이고 활성 시청 중 `EXTEND_STREAM`으로 만료 전에 연장한다. 서버·MQTT 장애 시 기기는 마지막 연장부터 최대 약 120초 안에 자체 종료한다.
- 여러 시청자 세션은 기기당 하나의 edge 송출을 공유한다. 세션 TTL·viewer count·stop 예약은 단일 서버 메모리, PostgreSQL 또는 Redis 등으로 구현할 수 있다.
- **Redis는 MVP 필수 의존성이 아니다.** 백엔드를 여러 인스턴스로 운영해 공유 TTL·원자적 viewer count가 실제로 필요할 때만 채택하고, 그전에는 선택한 저장 방식과 재시작 시 cleanup 정책을 문서화한다.

### 3.2 라이브 HLS 재생 인가 원칙

- 재생 자격은 StreamSession 소유자와 대상 기기의 `ACTIVE DeviceMembership`, `READY` 상태에 함께 종속된다.
- 미디어 계층은 playlist·segment 요청마다 백엔드에 확인하거나 매우 짧은 불투명 introspection token으로 동등하게 확인한다. `CLOSED/EXPIRED` 또는 권한 회수 뒤의 새 요청은 즉시 거부한다.
- 다른 시청자의 세션은 유지한다. 이미 단말에 전달된 바이트는 기술적으로 회수할 수 없다.
- 라이브 HLS 자격은 1~5분짜리 저장 영상 S3 서명 URL과 다른 계약이며, 객체 저장소 URL처럼 저장·재사용하지 않는다.

## 5. 외부 서비스 채택 체크리스트

- [ ] 개인정보 처리 위치와 보관 기간을 확인했다.
- [ ] 입력 데이터가 모델 학습에 사용되는지 확인했다.
- [ ] 사용자 동의·철회·삭제 흐름을 설계했다.
- [ ] 무료 한도, 예상 비용, 초과 차단 정책을 정했다.
- [ ] 장애 시 핵심 MVP가 동작할 폴백이 있다.
- [ ] API 키의 발급·회전·폐기 담당자가 정해졌다.
- [ ] 약관상 얼굴·음성·미성년자 데이터 처리가 허용되는지 확인했다.
