## 1. 전체 요약

빵긋은 가정에 설치된 홈캠이 웃음을 감지하고, 해당 순간의 영상을 저장해 가족 구성원이 앱에서 조회·재생·편집할 수 있도록 하는 서비스다.

현재 백엔드와 Flutter의 MVP 기능은 대부분 코드로 구현되어 있다. 기기 bootstrap/enrollment, 사용자 기기 등록, MQTTS 상태 보고, 라이브 스트리밍은 Jetson 실기 연동까지 확인했다.

다만 다음 항목은 아직 전체 파트의 종단 연동이 끝나지 않았다.

- 웃음 영상의 최종 MP4 mux, MinIO 업로드 완료, 앱 목록 반영
- AI 감지를 운영 MQTT `/events`로 전달하는 흐름
- 원시 감지 이벤트 통계의 Flutter 연결
- 실제 GPIO 등록 버튼과 코드 표시 모듈
- 실제 팬/틸트 모터 PWM 제어
- 최신 로컬 브랜치의 원격 반영 및 서버 배포

### 상태 표기

- `완료`: 코드 구현과 필요한 실기 또는 파트 간 연동까지 확인
- `코드 완료`: 코드와 단위 테스트는 있으나 실제 종단 연동 필요
- `연동 필요`: 한쪽 파트만 구현되어 상대 파트 작업 필요
- `미구현`: 구현해야 함

## 8. 이메일 초대와 MEMBER 요청

실제 이메일 전송 서비스는 사용하지 않는다. 이메일은 초대를 수락할 수 있는 계정을 고정하는 식별자로 사용한다.

### OWNER 초대

```text
OWNER가 이메일 입력
→ PENDING 초대 생성
→ 해당 이메일 계정이 앱 받은 초대함에서 확인
→ 수락 시 MEMBER
```

- 초대 유효기간 7일
- 다른 이메일 계정은 수락 불가
- OWNER는 수락 전 초대 취소 가능
- 초대 수락·거절·MEMBER 권한 회수 지원

### 사용자가 먼저 MEMBER 요청

```text
요청자가 앱에서 요청 링크 생성
→ OWNER에게 링크 공유
→ OWNER가 링크 클릭
→ 가족 초대 화면으로 이동
→ 요청자 이메일 자동 입력
→ OWNER가 최종 초대 발송
```

보안 처리:

- URL에 이메일을 넣지 않음
- 256비트 임의 토큰 사용
- DB에는 SHA-256 토큰 해시만 저장
- 24시간 유효
- 1회 사용
- 새 링크 생성 시 이전 미사용 링크 취소
- OWNER만 요청자 이메일 조회 가능
- 링크만으로는 기기 권한이 생기지 않음

### 사용 기술

- Spring REST API
- PostgreSQL, Flyway V20
- Flutter App Links
- Android Custom Scheme
- Share Plus

## 9. MQTT 역할과 인증

MQTT는 작은 상태·이벤트·명령만 전달한다. MP4 파일은 MQTT로 전송하지 않는다.

### MQTT가 전달하는 정보

- 기기 ONLINE/OFFLINE 상태
- 30초 heartbeat
- 녹화 상태, 버퍼 길이, 업로드 큐 깊이
- 화면 내 인원 수
- 등록 모드
- 웃음·호출어·터치·수동 원시 이벤트
- 라이브 시작·연장·종료 명령
- 명령 ACK
- 스트림 READY·STOPPED·ERROR

### 접속 정보

| 항목 | 값·규칙 |
| --- | --- |
| 프로토콜 | MQTTS |
| 운영 포트 | `8883` |
| Username | `deviceId` UUID |
| Password | 현재 `DEVICE_BEARER_TOKEN` |
| Client ID | `deviceId` UUID |
| 서버 검증 CA | `MQTT_CA_CERT` |
| 토픽 루트 | `{env}/wj/v2/devices/{deviceId}` |
| 운영 환경 | `prod` |

### 주요 토픽

```text
prod/wj/v2/devices/{deviceId}/status
prod/wj/v2/devices/{deviceId}/heartbeat
prod/wj/v2/devices/{deviceId}/registration
prod/wj/v2/devices/{deviceId}/events
prod/wj/v2/devices/{deviceId}/stream/events
prod/wj/v2/devices/{deviceId}/commands/ack
prod/wj/v2/devices/{deviceId}/commands
```

### ACL

기기는 자기 `deviceId` 토픽에만 publish/subscribe할 수 있다. 다른 기기 토픽과 와일드카드 구독은 허용하지 않는다.

### 현재 Credential 설계 주의점

현재 MVP는 하나의 `DEVICE_BEARER_TOKEN`을 다음 두 곳에서 함께 사용한다.

- IoT REST API Bearer Token
- MQTT 기기 비밀번호

현재 구현과 Dynamic Security ACL로 동작하지만, 장기적으로는 HTTP Token과 MQTT Password를 분리하는 것이 더 안전하다.

## 11. 원시 감지 이벤트

원시 감지 이벤트는 웃음이 감지됐다는 사실이고, 영상은 그 이벤트로 만들어진 MP4다. 두 기능은 중복이 아니다.

지원 타입:

- `LAUGHTER`
- `WAKE_WORD`
- `TOUCH`
- `MANUAL`

```text
원시 이벤트
= 감지가 발생했다는 기록

이벤트 영상
= 감지 시점 주변을 잘라 생성·업로드한 MP4
```

클립 생성이나 업로드에 실패해도 감지 자체는 통계에 남아야 하므로 별도 `device_events` 테이블을 사용한다.

### 현재 연동 공백

Backend는 MQTT `/events`를 검증·저장할 수 있다. 하지만 현재 `run_edge_ai_mvp.sh`는 AI가 운영 MQTT에 별도 연결하지 않도록 되어 있다.

현재 HTTP 영상 업로드 요청이 먼저 오면 Backend가 `sourceEventId`로 최소 이벤트를 복구한다. 따라서 업로드 요청까지 도달하지 못한 감지는 서버에 기록되지 않는다.

권장 연결:

```text
YAMNet
→ 로컬 IPC 또는 영속 파일 큐
→ wj-device-agent
→ production MQTT /events
```

AI가 동일 `deviceId`로 별도 MQTT 연결을 만들면 기존 device-agent의 Client ID와 충돌할 수 있다. device-agent가 운영 MQTT 연결을 하나만 소유하는 구조가 적합하다.

## 12. 감지와 업로드 실패 구분

### AI 미탐

- 실제 웃음을 AI가 감지하지 못한 상태
- 이벤트가 생성되지 않음
- 서버에도 기록되지 않음

### 로컬 클립 생성 실패

- 감지는 했지만 영상 구간 보호 또는 MP4 생성에 실패
- 원시 이벤트의 `localClip.state=FAILED`
- MQTT `/events` 연동이 되어야 서버에 남음

### 영상 업로드 실패

- MP4는 있지만 MinIO PUT 또는 complete에 실패
- 영상이 `UPLOADING`에 머묾
- 기본 30분 후 Backend가 `FAILED`로 전환
- 같은 이벤트 ID로 재시도 가능

`감지 실패`라는 하나의 상태는 없으며, `AI 미탐`, `클립 생성 실패`, `업로드 실패`를 구분해야 한다.

```text
→ POST /api/iot/videos/upload-url
→ MinIO Presigned PUT URL 반환
→ 기기가 MinIO에 직접 PUT
→ POST /api/iot/videos/complete
→ Backend가 실제 객체 크기·체크섬 확인
→ READY
```

### 계약

- 최대 500 MiB
- `video/mp4`
- `sourceEventId`는 UUID
- `Idempotency-Key=sourceEventId`
- 크기와 SHA-256 필수
- 같은 이벤트의 중복 요청은 같은 영상으로 처리
- READY 상태만 재생 가능
- 중단된 업로드는 `FAILED`로 전환 후 같은 이벤트로 재시도

IoT에는 MinIO Access Key나 Secret Key를 전달하지 않는다. MinIO Credential은 Backend만 보유하고 IoT는 단기 Presigned URL만 받는다.

## 16. 라이브 스트리밍

### 처리 흐름

```text
Flutter
→ 시청 세션 생성
→ Backend가 MQTT START_STREAM 발행
→ device-agent가 FFmpeg 릴레이 실행
→ MediaMTX RTSP ingest
→ HLS 변환
→ Backend가 단기 시청 토큰 발급
→ Nginx introspection
→ Flutter Video Player
```

### 구현 기능

- 스트림 `PENDING`, `READY`, `FAILED`
- 구조화된 `failureCode`
- 시청자 heartbeat
- Viewer TTL 45초
- Idle timeout 60초
- Edge hard lease 120초
- 유실 가능성을 고려한 START 재전송
- MQTT publish 실패 처리
- 기기 오프라인 오류
- 세션·streamId에 귀속된 단기 HLS 토큰
- HLS introspection
- 앱 종료 시 세션 정리

### 상태

| 항목 | 상태 |
| --- | --- |
| 앱→Backend→MQTT→Jetson | 완료 |
| Jetson FFmpeg→MediaMTX | 완료 |
| MediaMTX→HLS→Flutter | 완료 |
| 영상·음성 실기 재생 | 완료 |
| 최신 세션 복구·오류 개선 서버 반영 | 필요 |
| Raspberry Pi 직접 RTSPS | 코드 존재, 실기 확인 필요 |

미디어 publish 인증은 MQTT Credential과 별개다. 실제 Jetson 검증은 SSH 키를 사용해 서버 loopback RTSP에 터널링했다. 직접 RTSPS를 사용하면 MediaMTX publish 전용 계정이 필요하다.

## 18. 파트별 전달 사항

### IoT·하드웨어

- 서버가 발급한 `deviceId` UUID 사용
- `DEVICE_BEARER_TOKEN`은 REST와 현재 MQTT 비밀번호
- MQTT Username과 Client ID는 `deviceId`
- `MQTT_PORT=8883`, `MQTT_ENV=prod`
- `MQTT_CA_CERT`로 서버 인증서 검증
- 등록 코드 표시 형식은 `XXXX-XXXX`
- 등록 버튼과 `TOUCH` 이벤트는 별도 입력
- 실제 GPIO 버튼과 표시 모듈 구현 필요
- AI 감지 `/events`는 device-agent를 통해 발행 권장

### AI

- `eventId`는 UUID이며 재시도해도 변경하지 않음
- `occurredAt`은 UTC ISO 8601
- `LAUGHTER`, `WAKE_WORD`는 confidence 필수
- `TOUCH`, `MANUAL`은 confidence를 보내지 않음
- 업로드 `sourceEventId=eventId`
- `Idempotency-Key=eventId`
- MP4 크기와 SHA-256 제공
- 동일 deviceId로 운영 MQTT에 별도 연결하지 않음
- 감지 결과를 device-agent에 전달할 로컬 IPC 또는 큐 필요
- 최종 mux·업로드·앱 목록 반영 검증 필요

### Frontend

- 기본 API 주소는 `https://i15e201.p.ssafy.io`
- 사용자 API는 JWT Bearer 인증
- OWNER/MEMBER 권한표에 맞춰 UI 노출
- 영상은 `READY`일 때만 재생
- 라이브는 `READY` 응답의 `playUrl` 사용
- 스트림 heartbeat 주기는 API 응답값 사용
- 연간 통계는 날짜 범위를 명시해 조회
- 원시 이벤트 통계 화면 연결 필요
- 로컬 편집본 보관함은 FE 로컬 저장소에서 구현
- MEMBER 요청 링크의 운영 Android 딥링크 검증 필요

### Backend·인프라

Git에 커밋하지 않고 secret으로 관리해야 하는 값:

- `JWT_SIGNING_KEY`
- `DEVICE_PROVISIONING_ADMIN_KEY`
- PostgreSQL Credential
- MinIO Access/Secret Key
- MQTT Backend 계정
- MQTT TLS 인증서·개인키
- MediaMTX publish Credential

운영 설정:

- `S3_PUBLIC_ENDPOINT`
