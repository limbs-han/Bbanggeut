## 문서 성격 (중요)

**이 5개 파일은 목표(to-be) 기획 문서다. as-built(현재 코드 그대로)가 아니다.**

- MVP 7단계(회원가입/로그인 → 기기등록 → 홈 라이브 → 이벤트 영상 확인 → 편집 → 다운로드 → 통계/리포트)를 뼈대로 재구성했다.
- **이미 구현된 항목**에는 기존 as-built 문서(코드 검증 완료)에서 가져온 실제 코드 경로를 그대로 병기했다 — 이 부분은 코드와 대조 없이 신뢰해도 된다.
- **FN-A38 Flutter 리포트 화면은 구현됐다.** `LaughReportContentScreen`이 기존 영상 목록의 `LAUGHTER` 항목을 단말 집계한다. **FN-S26/API-51 서버 집계는 [제안·미구현]**이며 존재하는 API로 가정하지 말 것.
- **FN-A40 4컷 만화도 앱만 구현됐다.** `features/comic/*`이 `API-52`·`API-53`을 부르지만 **서버가 없다** — `--dart-define=COMIC_SERVER=true`를 주지 않으면 가짜 응답으로 동작한다. 서버를 만들 때는 `04-api-spec.md` 6절의 계약(앱 코드에서 확인한 사실)에 맞출 것.
- 실제 구현 작업에 착수하기 전에는 **반드시 최신 코드와 대조**해야 한다 — 이 문서는 2026-07-27 기준 스냅샷이며 이후 코드 변경을 반영하지 않는다.

## 사용 원칙

- ID(REQ-F/NF, FN-A/S/E/H, API, MQTT)는 4개 문서 및 사람용 원본(`../사람이 읽을 문서/`) 전체에서 동일하게 유지된다. 사람용 원본이 사실·ID·구조의 1차 원천이며, 코드 변경 시 사람용 원본을 먼저 갱신하고 본 디렉터리는 그 파생본이므로 함께 갱신할 것.
- FN-A38을 미구현으로 되돌리지 않는다. FN-S26/API-51의 **[제안·미구현]** 배지는 유지한다 — 서버 집계의 정렬 기준, 베스트 클립 개수 등은 아직 초안이다.
- `API-06`(`PATCH /api/auth/me`)은 서버에 매핑이 없다 — 본문에서 제외했으며 `04-api-spec.md` 부록에 경고를 유지한다.
- 코드 사실(미사용/스텁/실험단계/클라이언트 미사용 등)에 대한 주석은 각 문서 본문에 그대로 남겨 에이전트의 오판을 방지한다.
