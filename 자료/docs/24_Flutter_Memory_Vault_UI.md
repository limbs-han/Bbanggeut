# Flutter Memory Vault 화면 전환

## 변경 목적

앱의 최상위 상태를 `selectedDevice`가 아닌 `selectedVault`로 변경한다.
기기 연결이 없어도 추억 금고와 과거 영상은 유지되며, 라이브와 신규
촬영만 사용할 수 없다.

## 초기 로딩

1. 로그인 후 `GET /api/vaults`를 호출한다.
2. 이전에 선택한 금고가 있으면 유지하고, 없으면 첫 금고를 선택한다.
3. 금고의 `devices`가 비어 있으면 `VaultArchiveScreen`을 연다.
4. 활성 기기가 있으면 기존 5탭 메인 화면을 연다.

금고가 하나도 없는 신규 계정만 전체 화면 기기 등록 흐름으로 이동한다.

## 기기 없는 금고 화면

- 금고 이름 표시
- `GET /api/videos?vaultId=...`로 과거 영상 조회
- “현재 연결된 기기가 없어요” 안내
- 새 기기 연결 버튼
- 새로고침 및 로그아웃

“연결된 기기가 없습니다. 추억 영상을 볼 수 없습니다.”라는 기존 동작은
사용하지 않는다.

## 기기 등록과 해제

- 기기 등록 상단은 투명 배경 빵긋 마스코트와 Owner·Member 흐름 설명을 표시한다.
- Owner·Member 선택은 둥근 분할 탭으로 표시한다.
- Owner 입력 카드는 시리얼 번호 두 칸, 장소 선택, 새 장소 추가를 한 영역에 표시한다.
- 기기 연결 버튼은 입력 카드 아래의 강조 버튼으로 표시한다.
- 기존 금고에서 등록하면 claim 요청에 `vaultId`를 포함한다.
- 최초 등록으로 금고가 없다면 `vaultId`를 생략하고 서버가 새 금고를 만든다.
- 등록 성공 안내의 “홈으로 가기”를 누르면 최초 등록과 설정의 추가 등록 모두
  홈 탭으로 이동한다.
- 등록 화면에서 선택한 장소 카테고리에 새 기기를 연결한다.
- 기기 해제 성공 후 `GET /api/vaults`를 다시 호출한다.
- 해제된 기기는 선택 목록에서 사라지지만 `selectedVault`와 영상 목록은
  유지된다.

## 홈 장소와 기기 선택

- 홈의 장소를 바꾸면 해당 장소에 연결한 카메라만 기기 목록과 라이브 카드에
  표시한다.
- `집`에 연결한 카메라는 `카페`를 선택했을 때 노출하지 않는다.
- 장소에 연결된 카메라가 없으면 다른 장소의 카메라를 대신 표시하지 않는다.
- 장소 목록과 기기별 장소 연결은 계정별 보안 저장소에 보관해 앱을 다시
  실행해도 유지한다.
- 장소 추가와 기기 연결 저장은 요청 순서를 보장해 최신 카테고리 연결이 이전
  저장 값에 덮이지 않게 한다.

## 설정 화면

설정 화면은 금고 기준으로 동작한다. `selectedDevice`가 `null`이어도 열려야
하므로 이 화면에서 기기를 강제로 참조하지 않는다.

- 가족 초대 카드에는 리본 장식을 표시하지 않는다.
- 가족 구성원 목록에서 OWNER 역할 배지 옆에는 왕관을 표시한다.
- 카메라 설정 행은 기기가 없으면 "연결된 기기가 없어요"를 표시하고 비활성화
- 접근 기록과 보관 구독은 금고 OWNER 권한으로 노출한다
- 금고가 있으면 `/api/vaults/{vaultId}/subscription`과
  `/api/vaults/{vaultId}/access-logs`를 사용하고, 기기 경로는 금고를 아직
  못 정한 세션의 대비책으로만 남긴다
- 기기 등록 해제 버튼은 연결된 기기가 있을 때만 표시한다

## 기기 접속 상태 갱신

기기의 ONLINE 여부는 Redis presence 키이며 heartbeat TTL로 만료된다.
앱이 시작할 때 받은 값을 계속 들고 있으면, 이미 오프라인이 된 카메라에
라이브 보기를 계속 권하게 된다.

- `refreshPresence()`가 `GET /api/vaults`만 다시 읽어 기기 상태를 갱신하며
  영상·구성원·초대 목록은 건드리지 않는다.
- 홈과 가족 탭으로 이동할 때, 그리고 앱이 다시 활성화될 때 호출한다.
- 조회에 실패하면 마지막으로 알던 상태를 유지한다.

## 실패를 성공으로 보고하지 않기

`_guard`는 전달한 작업이 예외 없이 끝나면 `true`를 돌려준다. 권한이나 선택
상태가 없다고 조기 `return`하면 아무 일도 하지 않은 채 성공이 되어, 화면에는
"초대를 보냈어요"가 뜬다. 이런 분기는 `requireOwnedVault`,
`requireSelectedDevice`처럼 `ApiFailure`를 던져서 처리한다.
