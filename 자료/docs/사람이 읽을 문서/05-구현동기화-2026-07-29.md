## 2. 라이브: WebRTC 우선, HLS 폴백

라이브 세션 생성·조회 API의 제어 흐름은 그대로다. 서버는 세션이 `READY`이고 viewer 만료 전일 때 동일한 접근 토큰을 붙인 두 URL을 반환한다.

- `whepUrl`: 앱이 먼저 시도하는 WebRTC/WHEP 재생 URL
- `playUrl`: WHEP 연결이나 ICE 협상이 실패했을 때 사용하는 HLS 호환 URL

앱의 `WhepPlayerController`는 recv-only video transceiver를 만들고 SDP offer를 WHEP endpoint에 `POST`한다. MediaMTX가 SDP answer와 세션 `Location`을 반환하면 앱은 영상을 재생하고, 화면 종료 시 해당 세션 URI에 `DELETE`를 보내 정리한다. 별도 WebSocket 시그널링 서버는 사용하지 않는다.

운영 네트워크는 다음처럼 분리한다.

- HTTPS 443: Nginx가 `/webrtc/.../whep` 시그널링을 MediaMTX 8889로 프록시
- UDP 8189: WebRTC 미디어/ICE
- TCP 8889: host loopback에만 바인딩하고 외부에 직접 공개하지 않음
- HLS: 기존 호환 경로 유지

## 4. 운영·배포 주의 사항

1. `master` Backend CI 성공 뒤 운영 배포 승인 작업이 생성되며, 명시적 승인 없이 배포하지 않는다.
2. 배포 산출물은 실행 JAR과 `backend-deploy.tar.gz` 두 종류다.
3. 배포 래퍼는 운영 서버의 JRE 환경을 전제로 하며 JDK `jar` 명령에 의존하지 않는다.
4. Nginx 설정 변경은 `nginx -t` 검증 뒤 활성화한다.
5. WebRTC 활성화 뒤에도 HLS를 제거하지 않는다. 서로 다른 네트워크 환경의 폴백 경로다.
6. PostgreSQL·MinIO의 기존 named volume은 유지하며 배포 과정에서 `docker compose down`으로 제거하지 않는다.
7. MinIO 버킷은 anonymous access를 끈다. 앱과 장치는 서버가 발급한 presigned URL만 사용한다.
