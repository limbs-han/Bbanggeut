# ADR-001. editor-api는 계산만 하고, 사용자 콘텐츠는 백엔드가 갖는다

- 상태: **채택** (2026-08-04)
- 관련: `video_editor/README.md`, `backend/BACKEND_STATUS.md`, `자료/docs/20_서버_자동_영상_편집_설계_및_1단계_검증.md`

## 맥락

editor-api는 "고정 5개 영상으로 편집 UI를 반복 검증하는 개발용 서비스"로 태어났다.
분석(음량·YAMNet·움직임·표정)과 자동 편집 추천이 Python 생태계(MediaPipe·PyAV·
OpenCV)를 요구했기 때문에 Spring 백엔드와 별도 프로세스로 두었고, 그때는 상태를
MinIO JSON으로 두는 것이 합리적이었다.

그 뒤 실서버로 승격되면서 **"이미 여기 저장 코드가 있으니"** 편집 초안 → 완성본 →
댓글까지 차례로 이 서비스에 붙었다. 경로 의존(path dependence)이다.

## 문제 — 증거

경계가 잘못 그어졌다는 신호가 코드에 남아 있었다.

1. **의존 화살표가 양방향이었다.** editor-api는 권한을 알기 위해 매 요청 백엔드
   `GET /api/videos/{id}`를 호출하고(60초 캐시, fail-closed), 알림을 보내려고
   백엔드 `/api/editor/events`를 역호출했다. 반대로 백엔드는 삭제 시 editor의
   키 접두사를 **직접 알고** 지웠다(`{"edit-analyses/", "edit-projects/",
   "edited-videos/"}`). API가 아니라 **저장소 레이아웃으로 결합**된 상태다.
2. **보관 만료가 없었다.** 원본 영상은 금고 정책(기본 30일, 구독 시 365일)으로
   만료되는데 편집 완성본은 **영구 보존**이었다. 개인정보 보관 원칙과 어긋난다.
3. **댓글 동시 작성이 유실됐다.** DB가 없어 `comments.json`을 읽고-붙이고-
   덮어쓰는 구조라 두 사람이 거의 동시에 쓰면 뒤 쓰기가 앞 댓글을 지웠다.
   `id = len(items) + 1`이라 같은 id도 생길 수 있었다.
4. **작성자 이름이 위조 가능했다.** users 테이블이 없어 앱이 보낸 표시 이름을
   그대로 저장했다.
5. **백그라운드 업로드가 운영에서 401이었다.** 완성본은 OS 백그라운드 작업
   (WorkManager)이 올리는데 세션이 없어 헤더를 붙일 수 없고, editor-api는 모든
   `/v1/*`에 Bearer를 요구했다. 즉 이 기능은 **깨진 채 배포돼 있었다.**

3·4·5는 독립된 버그가 아니라 **오배치의 증상**이다. 백엔드에 있었다면 트랜잭션
INSERT와 `users` 조인, presigned URL(서명이 URL에 있어 헤더 불필요)로 애초에
생기지 않았다.

## 결정

**editor-api의 정체성을 "무상태 미디어·AI 워커"로 고정한다.**

| 남는다 (계산) | 옮긴다 (사용자 콘텐츠) |
| --- | --- |
| 영상 분석(4단계) | 완성본 MP4·메타 → `videos` 테이블의 `EDIT_OUTPUT` 행 |
| 자동 편집 추천 | 완성본 목록 → `GET /api/vaults/{vaultId}/edits` |
| 서버 렌더링(잠든 기능) | 재생 → 원본과 같은 `POST /api/videos/{id}/play-url` |
| 4컷 만화 워커 | 댓글 → `video_comments` 테이블 + `GET·POST /api/videos/{id}/comments` |
| 편집 초안 레시피(당분간 유지) | |

판단 기준을 한 줄로: **권한·보관·삭제·알림이 필요한 것은 시스템 오브 레코드
(백엔드)에 둔다. 계산은 워커에 둔다.**

만화 워커는 처음부터 이 원칙을 지킨 사례다 — 앱이 editor-api를 직접 부르지 않고
Spring 게이트웨이가 인증·금고 권한을 확인한 뒤 presigned URL을 붙여 넘긴다.
새 기능은 이 모양을 따른다.

## 결과

- 편집 완성본이 원본 영상과 **같은 경로**를 탄다: 금고 권한, 보관 만료
  (금고 정책 상속), 삭제 연쇄, 목록, presigned 재생.
- 댓글은 INSERT 한 번이라 유실이 없고, 작성자는 토큰의 사용자 UUID로 기록되며
  표시 이름은 서버가 `users`에서 조인해 준다 — 위조 불가.
- 백그라운드 업로드가 presigned URL로 동작한다(헤더 불필요) — **401 해소.**
  완료 통보를 부를 주체가 없으므로 서버가 객체 도착을 훑어 READY로 승격한다.
- editor-api는 DB가 없어도 되는 상태를 유지한다(의존성에 DB 드라이버 없음).

### 남은 부채

- **편집 초안 레시피**는 아직 editor-api의 MinIO에 있다. 추천 엔진이 만드는
  산출물과 같은 스키마라는 응집성 논거가 있어 우선순위를 낮췄다. 사용자 데이터
  라이프사이클이 필요해지면 함께 옮긴다.
- **서버 렌더링**은 앱이 아직 쓰지 않는다. 쓰기 시작할 때 산출물을 백엔드
  업로드 예약에 실어 `videos` 행으로 편입해야 한다.
- 백엔드가 삭제 시 editor 버킷 접두사를 아는 결합은 남아 있다(분석 캐시·초안
  정리). 초안까지 옮기면 사라진다.

## 대안과 기각 이유

- **모두 editor-api에 두고 자체 DB를 붙인다** — 사용자·금고·권한 테이블을
  복제해야 하고, 두 시스템 오브 레코드가 생겨 정합성 문제가 커진다.
- **모두 백엔드로 합친다(editor-api 폐지)** — MediaPipe·PyAV 런타임을 JVM으로
  가져올 방법이 없다. 분리 자체는 옳았다.
- **현상 유지** — 위 5개 문제 중 3·4·5가 실제 결함이고, 5는 기능이 깨진 상태였다.
